# PERF3B：后台准备语义正文

> 2026-10-16；基于已合并 PERF3A / PR #9（7446e12）。本批功能与数据边界通过，不代表整个 PERF3 或 P0 完成。

## 验收例子

1. 章节、选区、扩展与正文渲染树来自同一份完整 Markdown 解析快照；支持全局引用定义、脚注、跨段 HTML 与原始位置，不按字符或换行拆文档。
2. 后台准备后，界面不再解析完整 Markdown；继续使用原 React 组件、URL 检查、图片/链接策略和源码位置属性。已有批注/选区/阅读编辑保持可追溯。
3. 所有非白名单 HTML 容器仍先占位，再进行 HTML5 树构造与清洗；对恶意 HTML、协议、属性、foster parenting 和占位伪造的输出与旧管线一致。
4. 准备期间切模式、换文件或正文变化取消任务；已排队的旧回复不能显示旧正文。失败仍可重试或切源码；等待中不开放旧锚点操作。
5. 同一源内容的状态变化不重建正文；模式切换及查找不修改三文件 bytes/mtime、不创建 sidecar。
6. 同机前后 1/5 MiB 各五次比较 Worker、正文 DOM、后续绘制帧、最长帧间隔和堆采样；保留退化结果，不把 Worker 完成当作全界面可响应。

## 设计复核

| Before | After | Why |
| --- | --- | --- |
| Worker 已完成章节分析，界面却再次全文解析 Markdown 和 HTML | 同一快照在 Worker 生成经清洗的正文树，界面仅绑定现有组件 | 减少主线程重复计算，保留文档级语义 |
| 后台分析完成即进入较长的同步正文准备 | 正文准备也属于可取消、可重试任务 | 让模式切换和换文件在准备期间继续响应 |

## 功能验证

- 类型检查和 286/286 单测通过。新增 3 项测试对照 10 组语料的新旧 HAST、React HTML 输出及 node.position，覆盖已知阅读 fixture、空内容、BOM/CRLF、重复选文、远端引用定义、脚注、嵌套 details/列表/表格、原始 HTML 跨段及危险容器。冻结原解析快照后仍可准备，structured-clone 往返保持一致，重复渲染结果相同。
- 21 组生产打包窗口 E2E 通过：PERF3B、PERF3A、PERF2、PERF1、UX6A、UX1–UX5、B1、A6、A7.1、A7.2、A7.3b、A7.4、A7.5、A8.2–A8.5。覆盖编辑、精确保存、锚点与批注、查找、离开保护、结构变化、三文件恢复及全图导出。
- 新专项捕获实际 Worker 的 HAST 回复；挂起时无可编辑旧正文，提交后标题 DOM 偏移与 Worker 一致；查找时原节点身份不变，切回相同文档复用完整投影。跨 80 个标题的末尾引用定义正确，危险 HTML 在 Worker 返回前已移除，普通 HTML 不能冒充占位而躲过查找。
- PERF2 回归继续覆盖过期回复、文档/模式/dirty 切换、失败重试和大单段落取消；PERF3A 回归保留完整字素、跨 inline、br/嵌套块、可见性更新、1000 项上限与查询取消。测试比较原文与 sidecar 的 bytes/mtime，缺失 sidecar 不创建。
- 420×360 正文与查找截图已检查，无页面横向溢出。没有改变全局样式、动画或编辑支持范围。

实际开发服务按 verification 技能核验的用户流程是：打开本地 Markdown → 窄 preload 文件读取 → Worker 生成同一源版本的安全投影 → React 正文与查找显示。

| 边界 | 状态 | 证据 |
| --- | --- | --- |
| Vite 开发服务 | 通过 | `VITE v7.3.6 ready in 264 ms`，使用真实打包 preload 打开开发 renderer |
| 文件 → Worker | 通过 | 捕获真实回复 `renderTree.type === root`，等待时正文保持未就绪 |

`out/qa/perf3b-dev-e2e.log` 输出 `PERF3B passed`；Vite 已停止。React 复核保留稳定 memo/plugin 身份、原组件及 URL 处理，不用额外 effect 镜像渲染树。直接依赖 `remark-rehype@11.1.2` 是已有锁定依赖的显式声明，锁文件只新增根依赖项，没有升级传递包。

## 失败与已知边界

- npm 离线提升直接依赖时缺少 registry 元数据，返回 ENOTCACHED；联网执行固定版本安装成功，无新传递依赖。
- 原 sanitize schema 未显式标注类型，直接接入严格 unified 管线后类型检查拒绝其宽数组推断；添加现有导出的 Options 类型后通过，白名单值与顺序未改。
- 新窗口测试把保存 DOM 引用的赋值结果交回 CDP，触发 Object reference chain is too long；增加 `void 0` 只留浏览器内引用后通过，不改产品逻辑或放宽断言。
- 完整安全 HAST 会增加传输及缓存负担；不把 renderer 堆采样等同于全应用内存或 RSS。React、DOM、布局/绘制仍在界面线程；本批没有虚拟化、分批挂载或源码输入优化。后续按剩余长任务继续，而不宣称性能门槛整体通过。

## 最终性能复测

同一 Windows 主机、1200×800 窗口及 focus emulation，基线为 PERF3A 安装包解出的应用，当前版为最终运行时代码的生产 package。前后各 1/5 MiB × 五次独立进程，无并行构建/窗口回归；1 MiB 为 1,058,744 字节和 205 标题，5 MiB 为 5,288,903 字节和 1024 标题。两版使用相同测量脚本与隔离文件，末尾撤销源码输入并检查三文件 bytes/mtime。

下表均为 **中位数 / 最差值，单位 ms**。首屏是标题 DOM 出现后的两次 rAF，并非所有异步核验完成；最长帧间隔是每次打开期间最大 rAF 间隔的汇总。Worker 的 analysisMs 本批包含新增 HAST 准备，旧版只有三个投影。

| --- | ---: | ---: | ---: | ---: |
| 加载反馈 | 125 / 129 | 101 / 135 | 120 / 122 | 120 / 121 |
| 首次正文 DOM | 950 / 960 | 720 / 740 | 3991 / 4033 | 3089 / 3117 |
| 首屏后续帧 | 1034 / 1047 | 798 / 819 | 4352 / 4417 | 3446 / 3480 |
| Worker 内分析与准备 | 206 / 214 | 212 / 213 | 949 / 960 | 954 / 964 |

正文准备后主线程不再全文解析的收益与“回复 → DOM”变化一致。5 MiB 首屏中位数改善约 21%，但依然约 3.45 秒，最长帧间隔最差 417 ms，不能宣告大文档性能目标通过。Worker 计算与回复后处理之外仍有等待，后续需要继续拆开启动/消息调度，以及 DOM、布局与绘制的长任务。

其余操作是从自动化命令开始至最终状态及两次 rAF 的壁钟耗时，含 CDP/轮询/帧等待，不能等同于纯算法耗时或单次物理按键延迟。使用原 PERF3A 查询、输入与撤销流程，本批未更改这些操作的实现。

5 MiB 多结果路径中位数慢 48 ms，打开查找最差也有退化，保留原始结果而不只展示首屏收益。源码输入本批未优化，测量变化不能代替输入热路径分析。查询期间最大帧间隔通常约 50 ms，不将自动化调度特征解释为持续 FPS 承诺。
