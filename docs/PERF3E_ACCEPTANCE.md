# PERF3E：卡片正文复用与画布规模验证

> 2026-10-18；基于已合并 PERF3D / PR #12（3591f58）。当前切片验收完成，整体性能门槛仍进行中。

## 验收范围

本批消除当前源码未变时重复提取卡片正文的工作，保持章节摘要、全文、几何和持久化行为。正文布局、首次加载调度及自动平排没有改动，不把完成缓存视为整体性能达标。

| Before | After | Why |
| --- | --- | --- |
| 场景构建与节点更新都重新解析各章节正文 | 当前源码与章节树共用一份按需正文缓存 | 尺寸反馈、选择、拖动与保存状态更新可复用已有正文 |
| 生成 160 字摘要先展开全文字符数组 | 只收集前 160 个 Unicode code point | 保持截取规则，减少长章节的临时分配 |
| 重复计算掩盖首次准备和保存的剩余成本 | 分开记录切换、查找、三次连续拖动及返回阅读 | 不以功能完成代替响应预算 |

## 原因与边界

本机基线诊断的卡片切换命令约 10.65 秒；CPU profile 的约 10.79 秒采样中，Markdown parse 调用链约占 9.55 秒，卡片正文函数调用链约占 8.14 秒。打包 bundle 中函数与源码对应已核对；这是一轮诊断，不与上一批 20.9 秒绝对耗时直接比较。

缓存只由当前 CanvasEditor 持有，绑定精确 source 字符串与同一只读 SectionTree。只存标题、摘要、完整纯文本及子章节数，不保留解析 AST；场景拒绝不同源码或章节树的缓存。正文变化建立新缓存，离开卡片视图后随组件释放；没有全局、跨文档或磁盘缓存。缺少缓存的核心调用和主进程导出继续使用独立提取路径。

保持按章节直接源码范围独立解析、顶层 HTML/definition/YAML 过滤、空白归并及原 160-code-point 摘要规则，不顺带修正引用解析或块边界显示。全文仍完整保留，不通过截断数据或隐藏卡片换取性能。没有新增依赖、IPC、schema、自动布局规则或保存写入路径。

## 验证设计

- 独立旧算法 oracle 对照空文档、无标题、前言、同名标题、Setext、CRLF、中文/emoji/组合字符、长摘要边界、局部与跨章节引用、HTML、列表、表格和代码。缓存结果只读；源码或树改变不能复用旧结果。
- 缓存/未缓存场景对照位置、内容偏移、尺寸、折叠、正文显示和隐藏箭头端点；原模型不变。
- 实际窗口以 200 张卡片、500 条高亮验证每张卡片对应自己的正文、全部适应全图、查找定位、三次真实指针拖动及画布撤销重做。打开/查找/适应不写三个文件；拖动只改变画布状态，Markdown/YAML bytes/mtime 不变，其他卡片及源基线保持。
- 同标题正文编辑后检查新卡片正文，dirty 时仍禁止画布写入；撤销后恢复原文和正文显示，三个文件保持不变。初次脚本误假定正文改变后仍绑定原 card-0，导致超时；按项目的保守 ID 匹配规则改为定位当前标题的投影后通过，未放宽产品匹配。
- 规模 fixture 沿用预存 20×10 网格，自动平排仍是未解决项。概览下全数可见不代表每张卡片文字都能在此缩放下阅读。
- 旧 PERF1/UX6A 测试启动时窗口曾处于隐藏状态，帧等待停住；只恢复测试主窗口后继续。UX6A 随后暴露已有竞态：重开文档后后台阅读尚未准备完成就选段，出现 null.scrollIntoView。选区 helper 增加实际目标可见的条件等待，保留所有草稿、取消、保存与三文件断言；没有修改产品行为。
- 回归期间用本地辅助脚本仅激活带测试参数的应用主窗口，解除隐藏/遮挡造成的帧停顿；不用于前述性能采样。A6 的原 window.resizeTo 窄窗断言连续两次超时，在缩窗前增加 Page.bringToFront 后通过，原尺寸、抽屉和数据断言不变。脚本与失败日志保存在 out/qa，未把窗口恢复当作产品修复。

## 计时与内存口径

同机 Intel Core i9-14900HX、1200×800 CSS px，旧版为 PERF3D 已验证安装包解出的 EXE，新版为本批 package。1/5 MiB 各交替五对，期间不并行运行构建或其他窗口测试。每次重新启动应用并使用独立临时文件；不启用 CPU profile 或强制 GC。

命令耗时包含自动化分发、条件等待和后续帧。拖动包含六步指针移动、逐步后续帧及落盘确认，不等于单个鼠标事件耗时；最长帧间隔单独报告。renderer 堆采样未强制 GC，不含 main、Worker、GPU 或 RSS。

另做独立 5 MiB GC 诊断：画布/阅读往返三轮，在各阶段结束后强制 GC 采样。该组不纳入普通耗时统计，也不能由三轮有限样本证明不存在泄漏。

### 退化与调度波动

5 MiB 打开阅读中位数 1944 → 2676 ms、全部高亮出现 1789.7 → 2645.7 ms，首次卡片后的堆采样 105 → 135 MiB；1 MiB 适应全图 48 → 90 ms。这些退化保留，不声称所有操作或所有阶段内存改善。阅读运行代码未改，但旧/新版均存在两组启动等待：Worker 请求发送至分析开始，旧版五次为 1096/1132/95/77/80 ms，新版为 26/1139/1074/1155/28 ms；500 条批注加载均约 1.1 秒。该现象与既有主进程工作和 Worker 启动调度波动相符，尚不足以确定因果或排除回归。

诊断先撤销三次拖动并核对原卡片位置，避免既有“左上角位置需自动布局”启发式改变后续场景。每轮显式请求 GC；首轮仍有暂时存活数据，不能只据它宣称长期内存收益。后两轮卡片堆较低，返回阅读接近基线，支持缓存随视图释放的设计；三轮采样不证明不存在泄漏，也不代表全应用内存。

独立新版卡片 CPU profile 总采样约 3446 ms，parse 调用链约 2781 ms，其中卡片正文函数约 931 ms、章节提取约 1861 ms。首次解析仍在界面线程。首次拖动的 main profile 总采样约 4782 ms，章节解析调用链约 3849 ms；事务 validateBundles 调用链约 2165 ms，准备与加载事务均会核验源和画布。函数对应已通过本批 ASAR bundle 与源码核对，调用链包含时间有重叠，不能直接相加。这些是单次诊断，不能替代前述五对普通样本。

下一批 **PERF3F 画布准备与保存核验**：先分解加载和事务重复解析，评估精确源快照内的投影复用及后台调度；保留三文件版本、摘要、外部修改、锚点歧义、部分写入恢复和 dirty 保护。补同等规模的首次切换、拖动至落盘、失败恢复及读取波动对照，再推进 UX6B → UX7 → UX8 → QA1。自动平排、真实中文 IME、物理多屏 DPI、干净安装/升级/卸载仍未通过，P0 未完成。
