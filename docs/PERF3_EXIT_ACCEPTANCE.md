# PERF3 退出验收

> 2026-11-06。设计复核第 3 批 PERF3 的本机工程退出条件已满足；不代表 P0 或发布验收完成。原始采样、失败及测量口径均保留。结构化结果见 [PERF3_EXIT_METRICS.json](PERF3_EXIT_METRICS.json)，实现决定见 ADR-048/049。

## 结果与实现

- 5 MiB / 200 可见卡片 / 500 高亮，实际输入至完整就绪后一帧的中位数：进入卡片 **2136 → 272 ms**，返回阅读 **352 → 48 ms**。编辑并撤销后进入卡片 **2201 → 204 ms**，返回阅读 **343 → 75 ms**。两条流程各五对，不能混为同一操作。
- 当前 40 份普通对照中的候选样本，加载反馈最差 **48 ms**、正常交互最长帧间隔最差 **88 ms**；5 MiB 首次/重复完整打开的自动化壁钟中位数 **2048/1961 ms**。加载期间真实 Worker 尚未回复时，五次进入源码均为 **7 ms**，交互最长帧最差 **13 ms**。
- 阅读 Worker 同一解析派生完整安全 HAST、选区/章节与可选画布文本投影；引用/定义等作用域敏感内容继续保留原逐节解析。正文仅按完整顶层语义块提交，完整就绪后开放范围操作。隐藏且 inert 的同文档正文可在精确源码撤销后复用，不能用旧偏移操作新内容。
- 非空批注读取、受限 YAML 和独立源码/摘要/锚点核验在主进程拥有的可终止 Node Worker 内完成；会话、版本与 revision 再次核对。保存、重定位、结构候选和恢复继续独立验证；精确源码缓存仅限当前版本，歧义继续拒绝。
- CodeMirror 6 保留完整 LF 模型和共享撤销，DOM 按可见源码行挂载。没有语法高亮、富文本保存或第二套历史。固定三项依赖及 lockfile；独立原型、完整源码复制/粘贴、BOM/CRLF/emoji、dirty、保存和冲突回归通过。
- 卡片每批最多 40 个节点，实际正文/外框测量齐全后才应用视口和开放操作。未变化的 data、几何和节点保留身份，操作按钮仅在选中卡片挂载；总览使用较粗网格。打开反馈先提交并留出完整绘制帧。没有新 IPC 或文件 schema。

## 范围、硬件与测量

- Windows x64；Intel Core i9-14900HX、32 个逻辑处理器，系统可见内存 16,873,545,728 字节，240 Hz 显示器。普通样本使用实际可见且未最小化的窗口、1200×800 CSS 视口，不并行构建、其他窗口测试、CPU profile 或强制 GC。
- 同机旧包/候选交替；1/5 MiB 各五对画布流程，含首次和同进程重复打开；另各五对完整查找/输入流程，共 40 份。源码实际 1,077,209 / 5,271,609 字节，BOM/CRLF、200 标题、500 高亮。新进程和新 user-data 不等于清空操作系统缓存。
- 200 张卡片使用预存 20×10 网格，实际 DOM、完整就绪及适应全图后的 200 个可见边界均核验。自动平排仍属 UX8；没有以隐藏未渲染内容通过验收。三次拖动之间分别等待保存，不能称为不受限制的连续拖动。
- 保留自动化壁钟和实际输入至完整就绪后一绘制帧。前者包含 CDP、点击准备和额外帧，不能直接用它替代用户输入延迟；两列均公开。源码输入另保留 beforeinput 至下一绘制帧的独立计时。
- **原整窗帧间隔继续保留。** AU 的 135/136 ms 分别在点击前 6/7 ms 已结束，原失败报告不改写。AU2 新增完整帧时间点，正常交互从首次实际输入起统计，跨输入帧计其输入后的部分，无输入步骤从测量开始统计；输入后的 GPU、渲染、异步任务与保存等待均保留，仍要求 ≤100 ms。AU2 两次输入前 137 ms 的整窗记录及对应交互 50 ms 见 JSON 的 `preparationFrameWarnings`。不能宣称整个自动化窗口从未出现 >100 ms 间隔。
- 普通、pending 与 GC 使用相同候选 ASAR：`500a83bc53d1bf5e2555b2abe8c5f54733858e8367cd661b4b628e4167239d3b`。旧包为已合并 PERF3G / PR #15 对应独立副本，ASAR `25427ce0b8246603674d75b4ec940af1e2db0a5346993fb1aee0febce7efffb2`。manifest 另记录脚本 SHA、每份结果及执行状态。

## 退化与内存解释

- 首次和重复打开的完整耗时增加：5 MiB 自动化中位数 1599 → 2048 ms、1515 → 1961 ms；1 MiB 806 → 1167 ms、696 → 1170 ms。完整语义分批、源码控件和投影保留有成本，仍满足本机 3 秒目标，不能宣称所有路径更快。无匹配查询也由 88 → 95 ms。
- GC 为独立诊断，每个版本/大小在一个进程内往返三轮。当前末两轮卡片保留堆稳定，阅读约增加 0.1 MiB/轮；该样本没有发现大幅逐轮增长，不证明不存在长期泄漏。5 MiB 末轮阅读 renderer 堆 **51.2 → 63.4 MiB**，体现保留正文/源码模型的代价。
- 普通样本没有强制 GC；5 MiB 返回阅读 renderer 堆最差点采样 **76 → 140 MiB**，进程 Private 合计最差 **1060.6 → 1134.5 MiB**。不能用 GC 后值覆盖这些退化。进程工作集合计可能重复计算共享页；点采样不是生命周期峰值，renderer 堆也不是全应用内存。
- 第一次拖动至保存确认仍约 1.52 秒，期间保存保护保持；后两次约 0.52/0.50 秒。原计划没有给保存完成设置新的硬预算，本批未把它标为即时保存。

## 功能、开发服务与包体

- 类型检查、311/311 单测、25 套打包窗口回归通过，含实际批注、源码共享撤销/恢复、外部冲突、结构预览/取消/保存、嵌套、箭头与全图 PDF/JPG/PNG。模式、查找及 dirty 期间的三文件 bytes/mtime 保护继续验证。
- 生命周期新增：部分挂载 inert/不能聚焦/不能保存；dirty 不注册隐藏 Range；精确源码撤销后 500 个原始 Range 与引文恢复。Worker 错误、取消、旧回复、重试和释放通过。pending 五次均在真实 Worker 回复前开始测量。
- 当前包回归曾暴露测试等待问题：UX2 提前点击保存、初始章节跟踪与手动目录滚动重叠；UX4 事务发布短暂 ENOENT。等待 helper 修正后原断言全部通过，原失败保留。A7.5/PERF3B 新文档等待、拖动前真实视口/命中检查也保留，不以固定延时或无效拖动替代用户操作。
- 开发服务首轮因 Worker-only 依赖迟发现而触发优化器重载，导致 dirty 生命周期失败；`vite.renderer.config.mjs` 提前优化这些解析依赖。`--force` 冷启动后 PERF3G / PERF3C 均通过，服务未再发出优化器重载。重建生产包的 ASAR 与正式采样逐字节一致。
- 最终 package、Squirrel make、make 后 5 MiB PERF3G 通过。Setup 154,827,776 字节，SHA-256 `E5723C5F003F861D8B4E5E98DA1FB19EE6EB85960A6757B76101F34E4B3C6261`，路径 `out/make/squirrel.windows/x64/MerMarkd-0.1.0 Setup.exe`。本地生成，不是公开发行。
- 三项用户原有修改的 SHA-256 与起始记录一致，排除在提交之外。

## 复现入口与原证据

在空闲窗口使用新的前缀，避免覆盖既有 manifest。普通样本和 GC/pending 分开运行。

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run package
$env:MERMARKD_PERF_COHORT_PREFIX='fresh-prefix'
node tests/e2e/perf3-exit-samples.mjs canvas
node tests/e2e/perf3-exit-samples.mjs loaded
node tests/e2e/perf3-exit-report.mjs fresh-prefix
node tests/e2e/perf3-exit-probes.mjs fresh-prefix pending
node tests/e2e/perf3-exit-probes.mjs fresh-prefix memory
```

实际证据：`out/qa/perf3-exit-au2-{canvas,loaded,pending,memory}-manifest.json`、`perf3-exit-au2-measurements.json`、`perf3-exit-au-regression.log`、`perf3-exit-au-unit.log`、`perf3-exit-av-{vite-perf3g,vite-perf3c,package,make,postmake-perf3g}.log`。打包使用此前已核验的本地 Electron ZIP；最终 `make -- --skip-package` 使用已验证的相同包。

H–AV 的探索与失败在 PROGRESS/DEVELOPMENT_LOG 和 `out/qa/perf3-exit-*` 保留，尤其 AC/AK/AU 的整组超标、被最小化的无效样本、不完整 AF2/AM、AS 无收益调度、Vite 首轮重载。没有挑选较快的单次复跑代替完整 AU2。
