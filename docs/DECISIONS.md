# MerMarkd 技术决策记录

本文件记录会影响后续实现或用户数据的决定。P0 原型未完成前，标记为“暂定”的决定仍需以实测结果复核。

## ADR-001：Windows 首发，Electron Forge + React/TypeScript

- 日期：2026-09-17；状态：P0 本机打包与安装验收通过；升级仍需重复验收。
- 决定：先用 Electron Forge、React、TypeScript 开发 Windows 桌面版，npm 管理依赖并提交锁文件。优先试用 Forge Vite 模板且固定版本。
- 理由：Electron 提供明确的 PDF 打印和页面捕获 API；本机 Node/npm/Git 可用，不依赖 Rust。Forge 可生成 Windows 安装包。
- 风险与替代：Forge Vite 插件目前标为实验性。P0 若打包或安装不稳定，在业务代码较少时换成 Forge Webpack 插件；不更换文档核心模型。
- 验证：启动、类型检查、package、Windows Setup.exe 安装与运行均已通过。本机卸载有 Squirrel 残留、启动有缓存权限警告，须在干净环境复测。首次 Electron 下载超时，使用镜像后完成。

## ADR-002：Markdown 与伴随画布文件分离

- 日期：2026-09-17；状态：暂定，待恢复实验。
- 决定：`.md` 保存正文和标题；同目录 `*.md.mermarkd.json` 保存卡片 ID、坐标、折叠和箭头。批注采用独立的 `*.md.annotations.yaml`，见 ADR-006。两类 sidecar 均记录对应的已落盘 `.md` 摘要；批注记录还保留各自锚点基线，允许明确的过期或混合基线但不得误用旧范围。未保存的相关状态进入恢复草稿。
- 理由：普通 Markdown 文件保持可独立使用，视图操作不改写正文。
- 风险与替代：三文件无法原子同时提交。保存采用基线摘要校验、事务日志、依次替换与恢复；P0 若不能可靠恢复，再评估将布局存入独立项目容器的方案。
- 验证：模拟每个写入中断点、双实例与外部修改，重开后无正文、批注或箭头丢失。

## ADR-003：保守执行章节结构变更

- 日期：2026-09-17；状态：已定产品原则，技术细节待 P0 验证。
- 决定：只在用户明确改变卡片容纳关系、预览确认后生成最小原文补丁。候选全文必须重新解析与校验；不安全场景阻止操作。多行 Setext 需转成 ATX 时首版不自动执行。
- 理由：Markdown 的相邻块、引用定义与标题语法会让简单字符串切片产生隐性语义变化。
- 验证：固定样本的移动/撤销字节往返、父子树与链接语义校验。

## ADR-004：独立导出场景

- 日期：2026-09-17；状态：暂定，待 P0 导出原型。
- 决定：交互画布与导出渲染器共享场景数据，不直接截图 React Flow DOM。导出场景使用 HTML 卡片和 SVG 箭头；PDF 先分页再打印；位图逐块捕获。Sharp 只在安装包中验证通过后用于单张拼接。
- 理由：视口裁剪、嵌套 DOM 与页面尺寸使直接截图无法保证完整导出。
- 验证：中文、图片、长卡片、跨页箭头、视口外节点、8k 以上场景与安装包内输出。

## ADR-005：阅读渲染与资源权限边界

- 日期：2026-09-17；状态：最小阅读切片已实测；2026-09-24 的 A7.1/A7.2 组合验收已完成，2026-09-25 完成 HTML5 foster parenting 与批注错误信息边界的安全收口。
- 决定：阅读界面使用 `react-markdown`、GFM 与 YAML frontmatter 插件；标题目录仍来自 `src/core` 的 Markdown 章节树。CommonMark + GFM 的受支持结构只显示语义结果，不显示标题/强调/链接/表格/围栏等源码标记；frontmatter 作为元数据从正文隐藏。所有非白名单原始 HTML 容器先在 Markdown AST 层替换为内部占位，再运行 `rehype-raw`；这样 HTML5 foster parenting 不能把被拒绝容器内的表格文字或资源节点移到容器外。HAST 元素策略随后兜底，`rehype-sanitize` 最后删除未允许的属性、协议和类名。白名单语义元素只保留受限属性；普通未支持标签显示“暂不显示”占位，`script`、`style`、`iframe`、`object` 等危险元素显示统一的安全占位，两类内容的整个子树都不作为正文提取。当前源码选区映射不解析原始 HTML，所以白名单 HTML 即使可阅读也不能建立高亮或批注；原始 HTML 标题不进入 Markdown 章节目录。对能够无歧义识别的已知未支持扩展给出文档级提示，其余内容按当前 CommonMark 方言的普通文本处理，不把源码泄露当作已渲染。用户可通过文件选择器或右上角明确的拖放区域打开单个本地 `.md`；拖放文件的真实路径由 preload 获取，主进程重新校验后载入。相对图片限在当前文档目录，外链仅允许 `http`、`https`、`mailto` 并交给系统浏览器。允许列表、属性和占位合同见 `READER_DIALECT.md`。
- 理由：Markdown 正文可能包含不可信链接或 HTML，需要让正文显示与本地文件权限分离，同时保持阅读无写入路径。
- 验证：早期切片的 UTF-8/BOM、危险协议、目录越界与打包版安全样本已经通过；A7.2 又验证了白名单语义、普通与危险占位、整棵子树不提取、原始 HTML 禁止批注及打包版回归。最终核心回归覆盖 HTML5 foster parenting，确认危险容器内的表格文字、图片和资源请求不能逃逸；完整命令与观察结果见 `PROGRESS.md`。

## ADR-006：批注使用独立 YAML sidecar 与保守源码锚点

- 日期：2026-09-17；状态：产品决定；A1 源码映射、A2 schema 与单文件保存、A4 高亮、A5 便签与标签写入及 A6 保守重定位与人工重选已实现；章节结构变更后的映射和跨文件事务仍待 P0 验证。
- 决定：每份 `example.md` 对应同目录 `example.md.annotations.yaml`；画布 JSON 保持独立。高亮与便签共享稳定 ID；可选一个标签。每个锚点持久化为原始 UTF-8 字节半开范围、该范围所属版本的 SHA-256、原文片段、前后文、可见引文和章节线索。屏幕位置只在渲染时计算；摘要不符的旧锚点先冻结为待定位，不能按旧偏移显示。
- 理由：Markdown 不被阅读标记污染；YAML 可随原文携带、由 Git 审阅，独立文件减少画布操作引起的无关差异。源码位置与上下文结合比 DOM 像素或纯文本搜索更可靠。
- 风险与替代：YAML 不能保证 Git 自动合并；源码与可见文字在格式标记处不一一对应，UTF-16/UTF-8/BOM 也需转换。先支持可精确映射的单块选区；不唯一时保留便签并进入待定位，不自动错贴。若 YAML 往返造成大范围 diff，调整序列化策略而不改 Markdown 存储原则。
- A2 实现约束：schemaVersion 固定为 1，UTF-8 sidecar 不超过 1 MiB；拒绝未知字段、注释、别名、显式标签和不合法范围。选区仅从当前已打开文档生成；保存时校验 Markdown 与 sidecar 双基线，原子替换单个 sidecar，冲突或写入失败时在应用数据目录保留候选草稿。A2 阶段原文摘要不符时整个 sidecar 只读；A6 增加重新载入后的审查流程，只有用户显式应用候选或人工重选才迁移到当前摘要，未定位记录继续保留旧锚点基线。
- 错误呈现边界：sidecar 读取、当前 Markdown 复核读取与 YAML 解析失败使用稳定错误码和固定自然中文提示进入阅读界面。原始 `error.message`、`sourceExact`、字节范围及 sidecar 绝对路径不能进入 `AnnotationDocumentView.reason`；详细诊断只留在主进程日志。失败状态保持只读，不以不完整数据继续定位或覆盖。
- 已知边界：`.lock` 文件在进程异常终止后可能残留；为避免误删其他实例的活动锁，A2 保守地拒绝再次覆盖并保留草稿，后续恢复流程需解决锁归属与安全清理。外部编辑器不会遵守锁，最终摘要复查缩小竞态但无法提供跨两个独立文件的原子事务。单个 Markdown 的草稿和安全替换在 A7.3a 验证；跨三文件的目录持久化与中断恢复要等 A8.1 的最小画布模型。
- 验证：重复选文、加粗/链接、中文/emoji、BOM/CRLF、外部编辑、删除/复制/移动章节、非法 YAML、双实例与中断写入样本；保存后 `.md` 原始字节摘要不变。

## ADR-007：混排使用语义布局，阅读装饰保持克制

- 日期：2026-09-17；状态：A3 Windows 打包版已通过实际 100%/125%/150% 缩放视觉验收；其他平台仍待验证。
- 决定：GFM 表格保留 `<table>` 单元格布局并在外层滚动；列表使用原生标记和固定缩进；代码块明确 tab 宽度与横向滚动。批注在边栏展示，低饱和度高亮不改变字宽和行高。默认不为全角/半角对齐改写 Markdown。
- 理由：不同字体、回退字形、emoji 和缩放下，字符宽度没有可靠的固定倍数；插入空格既会破坏原文，也不能保证阅读视图对齐。
- A3 实现：保留语义 `<table>`，由可聚焦的外层容器承接横向滚动；GFM 数值列沿用单元格对齐。列表使用浏览器 marker、统一缩进和任务框布局；代码块保留原始长行并设置 `tab-size: 4`，在自身区域横向滚动。窄窗口目录改为单行横向章节栏，避免挤占阅读正文。布局只改阅读 DOM/CSS，不变更 Markdown 或批注数据。
- A3 验证：打包版在 1200×800、约 800×600 的实际窗口及 Electron 100%/125%/150% 缩放下，表格列和 9–12 列表标记保持对应，表格/代码可分别滚动，整页无横向溢出；选区映射回归与原文 SHA-256 均保持不变。
- 验证：中英文、全半角标点、长 URL、emoji/组合字符、两位数及嵌套列表在窄窗口与 100%/125%/150% 缩放下无错列、遮挡或裁切，原文件摘要不变。

## ADR-008：高亮以原文锚点还原为阅读视图范围

- 日期：2026-09-18；状态：A4 Windows 打包版验收通过；其他平台与大量记录仍待验收。
- 决定：高亮继续保存为批注 YAML 中的源码字节锚点。加载时先校验原文摘要与锚点原文，再把锚点反向映射为唯一的可见文字范围；只有字节范围、原文片段和可见引文都精确回环，才用 CSS Custom Highlight API 给阅读 DOM 的 `Range` 着色。无法还原的位置显示待定位，不搜索相同文字后猜测位置。
- 理由：着色不增删 Markdown 字节，也不向正文 DOM 插入包装节点，保留 A1 的选区映射与原有排版。重复文本由源码字节位置区分，外部编辑后旧范围冻结。
- 交互：四色低饱和背景；交叠处按固定优先级显示一个背景，当前选中的记录优先；列表可通过键盘跳转、改色、删除。系统高对比模式改用系统高亮色。仅暴露加载与高亮增改删的窄 IPC；主进程拒绝待处理草稿、只读 sidecar、过期源摘要或不一致的磁盘基线。
- 边界：A4 仍以精确可映射的单个标题或段落为限，复杂节点和跨块选区留给后续切片。A6 已为旧锚点增加严格唯一候选和人工重选；重复、上下文变化、非渲染区域或碰撞仍保持待定位。浏览器无 Custom Highlight API 时明确提示且停止创建，以免出现保存成功却不可见的标记。
- 验证：打包版以 BOM+CRLF 样本实测普通、格式化、重复、emoji、重叠、文末和键盘选区；改色删除后重启恢复正确。模拟系统高对比模式可读；外部改源后旧记录待定位且注册表无着色；高亮操作前后 Markdown SHA-256 不变。构建与单元测试结果见 `PROGRESS.md`。

## ADR-009：便签与标签采用单候选写入和响应式批注边栏

- 日期：2026-09-23；状态：A5 已实现；A6 已补足保守重定位、人工重选与阅读摘要。
- 决定：同一精确锚点最多有一条便签。已有高亮转换为 `note` 时保留稳定 ID、锚点、`createdAt`、记录顺序和颜色；直接创建的便签可以没有颜色。新标签与便签创建或便签更新先组成同一个内存候选，再只保存一次 sidecar；磁盘冲突时完整候选进入恢复草稿。删除便签不自动删除未使用标签。
- 标签语义：创建标签时去除首尾空白并规范化为 NFC；同大小写且 NFC 等价的名称复用已有标签，大小写不同的名称可以并存。便签上限为 32 KiB UTF-8，标签名上限为 256 UTF-8 字节，v1 最多 200 个标签。
- 交互：便签正文和标签只作为纯文本渲染。宽窗口的批注边栏进入页面正常布局；宽度不超过 1100 px 时使用带焦点循环、Escape 关闭与焦点返回的抽屉。原文跳转使用经源码锚点反向核验的 DOM Range，不依赖该便签是否有高亮颜色。待定位记录继续显示引文、便签和标签，但不允许跳转、编辑或删除。
- 理由：一个候选和一次保存避免出现“标签已写入而便签失败”的半成品；原位转换避免同一选区出现重复记录；边栏普通文档流保证多条便签不覆盖正文或彼此遮挡。
- 验证：领域测试覆盖高亮原位转换、直接无色便签、新标签与 NFC 复用、编辑、删除、限制和无操作更新时间；打包版交互与文件边界结果见 `PROGRESS.md`。

## ADR-010：重定位候选显式提交，阅读摘要只产生剪贴板文本

- 日期：2026-09-23；状态：A6 已实现并通过 Windows 打包版 E2E；应用内编辑映射已由 ADR-015/A7.4 补足，章节结构变更留待 A7.5。
- 重定位决定：原文摘要变化后，只有 `sourceExact` 在当前完整源码中恰好出现一次、锚点保存的左右上下文均仍精确相邻、候选可反向还原为当前阅读 DOM 的唯一范围，并且不会与其他记录落到同一范围时，才提出“可安全重定位”。旧字节位置和 `sectionHint` 不参与重复候选消歧。删除、复制后重复、任一侧上下文变化、非渲染区域和目标碰撞都继续待定位。
- 提交与持久化：候选在载入时仅供审查，不自动改写 sidecar。用户显式应用后，成功候选改用当前原文摘要和字节范围；未解决记录保留旧 `basisSha256` 及全部内容，允许同一 sidecar 明确保存混合锚点基线。保存同时校验当前 Markdown 摘要、当前 sidecar 字节摘要和迁移前的 `source.sha256`；冲突不覆盖磁盘文件，并保留完整候选草稿。
- 人工重选：用户可把待定位高亮或便签绑定到当前可精确映射的单块选区。操作保留记录 ID、`createdAt`、记录顺序、便签、标签与颜色，只替换锚点并更新 `updatedAt`；新目标已被其他记录占用时拒绝。
- 摘要决定：主进程根据当前已核验状态生成 Markdown，并通过 Electron 剪贴板写出。摘要沿用边栏的“全部 / 无标签 / 指定标签”筛选；已定位记录按当前字节位置排序并用当前章节路径分组，待定位记录按 sidecar 顺序置于末尾并显示旧章节线索。引文、标签和便签均转义为纯 Markdown 引用；写入剪贴板前再次核对当前窗口仍绑定同一 `DocumentSession`，文档已经切换时终止复制。复制摘要不修改 `.md` 或 sidecar。另存摘要文件以后单独实现。
- 理由：严格候选和显式提交把“错贴数为零”放在召回率之前；混合基线避免顶层摘要更新后误把旧范围当作当前范围；人工重选恢复无法证明的记录，剪贴板摘要则在不引入新持久文件的情况下形成可携带阅读产出。
- 已知边界：A6 的外部变化审查不做通用文本补丁映射，不使用章节线索放宽重复文本匹配；应用内显式保存使用 ADR-015 的独立保守包络。人工重选仍受 A1 单块标题/段落映射范围限制。摘要只复制到剪贴板，几百条记录的性能与另存文件尚未验证；章节移动留待 A7.5，三文件事务留待 A8.1。
- 验证：重定位、混合基线、碰撞、人工重选、摘要过滤/排序/转义及旧 sidecar 迁移的领域测试均通过；全套 `npm test` 79/79、`npm run typecheck`、`npm run package` 与 `npm run make` 通过。`tests/e2e/a6-packaged.mjs` 在 Windows 打包程序中验证 6 条批注、3 条安全候选、人工重选后 2 条待定位、全部及标签筛选摘要、同名章节分组、外部 sidecar 冲突保留 1 份草稿和 800×600 级窄窗口无横向溢出。Windows 测试安装包为 153,850,368 字节。

## ADR-011：三模式按用户任务分离并共享一个文档会话

- 日期：2026-09-24；状态：产品决定；A7.1、A7.2、A7.3a、A7.3b 与 A7.4 已完成对应验证；阅读和编辑模式已实现，卡片模式尚未实现。
- 模式职责：阅读模式呈现无源码语法的语义正文并承载高亮、便签、标签、摘要和锚点修复；编辑模式逐字显示完整 Markdown 源码，不渲染正文，负责输入、查找替换、撤销重做和显式保存；卡片模式负责标题派生卡片、布局、折叠、箭头和完整场景导出，只有预览确认的结构命令可改 Markdown。
- 共同外壳：打开/拖入、文件名、外部变化、未保存/冲突状态和模式切换不属于某个模式。搜索按当前模式分派。切换模式本身不写 `.md`、批注 YAML 或画布 JSON。
- 当前位置：三种模式共享 `DocumentSession`、章节树和当前章节；阅读滚动、编辑器光标与卡片选择转换为可核验的源位置。当前模式、章节、文字选区、批注和卡片必须有非纯颜色反馈及适当 ARIA 状态。
- 编辑草稿：编辑器维护会话内唯一源码缓冲区，不让各视图复制正文状态。dirty 时阅读模式只能显示明确的“未保存预览”，暂停依赖已落盘摘要的批注和结构写入；卡片模式只能显示只读结构预览，禁用布局持久化、连线、结构操作和导出。显式保存核验磁盘基线、BOM、换行和候选解析后才替换 Markdown。单 Markdown 崩溃草稿属于 A7.3a；跨 Markdown/YAML/JSON 的事务恢复属于 A8.1。无操作保存必须保持字节摘要不变。
- 选择反馈：阅读正文有选区时即时核验并显示轻量操作；无选区不常驻操作条。不支持范围用自然语言拒绝，不显示字节偏移或 `sourceExact`，也不搜索同名文字猜测位置。源码行列信息只进入编辑模式；PDF/JPG/PNG 导出只进入卡片模式。
- 理由：按用户任务分离可避免阅读页被源码和工程状态打断，也避免在源码编辑器或卡片画布中误触批注写入。共享会话和源位置使三种投影保持一致，并把文件写入继续留在已有摘要校验边界内。
- 后果与顺序：A7.1 已把共享外壳、无源码诊断的阅读流、即时选区和滚动章节状态落地；A7.2 已固定阅读方言、安全 HTML 与可见正文查找；A7.3a 已验证安全保存和单文档草稿，A7.3b 已开放纯源码编辑并落实 dirty 写入边界；A7.4 已完成应用内编辑到批注锚点的保守映射。A7.5 处理章节源码变换；A8.1 固定画布模型并验证三文件恢复，A8.2 实现嵌套画布与关系持久化，A8.3 单独实现全图导出。阅读和编辑模式现可进入；卡片入口仍必须明确标为尚未实现。
- 验证：同一 fixture 在阅读 DOM 中不出现受支持结构语法，在编辑器中完整显示源码；模式切换不写文件；有效/无效选区、滚动章节、键盘、高对比和窄窗口均有确定反馈；BOM/CRLF/无尾换行的无操作保存摘要不变，外部冲突不覆盖。

## ADR-012：正文查找只索引当前可见的阅读语义

- 日期：2026-09-24；状态：A7.2 已完成并通过打包版验收。
- 决定：阅读查找由共享外壳中的 `Ctrl+F` 入口启动，只遍历 `.markdown-body` 中实际具有可见布局的文本节点。目录、文件状态、批注 UI、frontmatter、HTML 占位、`hidden`/`aria-hidden` 内容和关闭的 `details` 不计入结果。查找按字面量、Unicode 不区分大小写、非重叠和字素边界执行；结果不能跨标题/段落/列表项/表格单元格/代码块等阅读块，也不能跨 `<br>`。最多保留 1000 项，达到上限时在搜索条明确说明。
- 交互：全部结果与当前结果使用独立 CSS Highlight 名称，当前结果所在阅读块另有轮廓作为非纯颜色反馈。Enter/Shift+Enter 或按钮在结果间循环；关闭搜索后焦点回到入口。正文查找不改变浏览器原生选区，不复用阅读批注选区，也不写 `.md`、批注 YAML 或画布 JSON。
- 理由：用户在阅读模式中查找的是当前能读到的语义正文。把目录、隐藏元数据、被安全策略丢弃的 HTML 或工具界面算入结果会产生无法看到或无法定位的命中；把搜索结果放进原生选区则可能与批注创建混淆。
- 边界：该索引随当前渲染 DOM 同步建立，不是全文搜索引擎。1000 项上限和块边界用于限制一次绘制的范围；大文档延迟仍需建立性能基线。A7.3b 已为编辑模式提供独立的源码查找/替换；卡片模式以后查找卡片，两者不得复用阅读 DOM 结果。
- 验证：领域测试应覆盖 Unicode 大小写、字面量元字符、非重叠、组合字符边界和结果上限；打包版应覆盖可见/隐藏正文、frontmatter、占位、关闭的 `details`、循环导航、Escape 焦点返回、强制颜色、窄窗口及查找前后所有内容文件摘要不变。最终命令和观察结果记录在 `PROGRESS.md`。

## ADR-013：单 Markdown 保存先持久化不可变草稿，再独占发布源文件

- 日期：2026-09-28；状态：A7.3a core/main 原型已完成测试、压力测试、类型检查、打包和打包版回归；A7.3b 已通过窄 preload/IPC 接入编辑 UI。
- 字节合同：Markdown 只按严格 UTF-8 解码，UTF-8 BOM 作为独立元数据保留；正文字符串中的 LF、CRLF、CR 和尾换行不被解码器或编码器规范化。编码拒绝不完整 Unicode 代理项。无操作保存再次读取磁盘并保持原始 SHA-256；单一换行格式不能在普通保存中被无意转换，混合换行源暂不覆盖。
- 草稿决定：每次候选先写入面向应用数据目录的唯一临时文件，执行文件级 `sync` 后，以硬链接发布为不可变 generation。发布目标已存在时失败，不覆盖任何 generation。并发分支各自保留；只有新 generation 已持久化后，才按旧草稿路径和精确 SHA-256 清理上一代。generation 与因发布/清理失败留下的孤立临时文件都可枚举、载入，并以精确 SHA-256 显式丢弃；原文被删除后仍可恢复候选。
- 源文件决定：保存候选草稿持久化后，核验 expected 源 SHA-256、严格 UTF-8、BOM、换行合同和章节解析。变更保存取得以 `wx` 创建并文件级 `sync` 的文档锁，再次核验源摘要；候选写入源目录的唯一临时文件并文件级 `sync`。随后将已核验源文件移动到同目录唯一 backup，核验 backup 摘要，再以硬链接把候选独占发布到空出的原路径。路径若被外部进程重建，硬链接返回冲突，外部文件不被覆盖；候选草稿和源 backup 保留供恢复。其他候选发布错误发生时，如果原路径仍为空，则以独占硬链接恢复精确 backup；若路径已重建或恢复失败，仍保留 backup。每次 `changed: true` 的成功保存也默认保留原文 backup，并在 `saved` 结果中返回 `sourceBackup`，不因一次保存后的摘要核验成功而自动删除。
- 恢复决定：源 backup 清单分别报告可读取项和不可读取/不可校验项。只有路径归属正确、SHA-256 与用户选择版本相符且当前不存在 document lock 时才能恢复或显式丢弃；恢复通过独占硬链接拒绝覆盖现有源路径。Markdown 保存锁记录 PID、owner token 和时间；活动 PID 锁保留，死 PID 锁可在检查后按精确锁 SHA-256 显式清理。格式未知的锁默认保留，只有调用方明确选择并提供精确 SHA-256 才允许删除。成功提交后的草稿/临时文件清理失败不得把已提交结果伪装为失败，而要返回保留物告警；源 backup 的保留属于正常成功结果，不是清理失败。
- 文件边界：原型只写单个 `.md`、其同目录临时文件/backup、文档保存锁，以及调用方指定草稿目录；不会创建或修改批注 YAML 与画布 JSON。单个源文件和候选上限为 32 MiB。Markdown、批注 YAML 和画布 JSON 的联合基线、事务日志与中断恢复仍属于 A8.1。
- 理由：单一可变草稿会让并发保存相互覆盖；在最终 SHA 检查后直接 `rename` 覆盖目标路径，仍可能覆盖外部进程在竞态窗口重建的文件。不可变 generation 保存每个候选，源 backup 保留已核验基线，独占硬链接发布则把“目标路径仍为空”交给文件系统判定。
- 限制：当前只对文件内容和上述摘要/路径状态作承诺。文件级 `sync` 不等于目录 `fsync`，不能承诺物理断电后目录项一定持久；外部进程若在移动前已持有旧 inode/句柄，仍可能在平台允许时延迟改写 backup，所以 changed save 必须保留 backup。A7.3b 已显示当前会话扫描到的候选草稿和本次 changed save 返回的精确 backup，并允许按 opaque ID 清理；应用仍不自动扫描、排序或清理所有历史 backup。新文件只沿用基础权限 mode，Windows ACL、ADS、其他元数据和原硬链接身份不会完整保留。当前工作目录没有 `.git` 元数据，无法用仓库 diff 或提交记录审计本批；现有 hash 命名 shadow copies 保持原样，并由 `tsconfig.json` 显式排除 `src` 下副本。
- 验证：聚焦样本应覆盖 BOM/无 BOM、LF/CRLF/无尾换行、无操作、超限、并发候选、外部变更、只读目录、缺失源、外部路径重建、非 `EEXIST` 发布失败后恢复原文、源移动后中断、changed save 返回并保留 backup、不可读 backup 清单、锁存在时拒绝恢复或丢弃 backup、草稿发布失败、清理失败、死/活动/未知锁，以及 sidecar 不变。最终命令和计数记录到 `PROGRESS.md`，未记录前不把 A7.3a 描述为已完成验收。

## ADR-014：源码编辑使用 LF 投影、单一会话缓冲区和主进程写入门槛

- 日期：2026-09-29；状态：A7.3b 已完成并通过 Windows 打包版 E2E。
- 源码与格式决定：P0 使用原生 `textarea` 承载完整 Markdown 源码，不在编辑模式渲染富文本。编辑器只操作 LF 投影；主进程会话保留打开时核验的 BOM、单一换行风格和尾换行，并在保存时按该 `sourceFormat` 重建字节。混合换行和超过 32 MiB 的文档保持只读，不能由普通保存隐式规范化。
- 会话与 IPC 决定：每个 `DocumentSession` 最多持有一个 `MarkdownEditorSession`。主进程生成 epoch，接受单调递增的 revision 和候选内容；渲染进程不能提供路径、expected SHA-256、BOM、草稿目录或 backup 路径。编辑器的正文只存在于这一份会话候选中，阅读模式的未保存预览读取同一候选。
- 持久化决定：输入按 revision 串行更新，并在约 700 ms 空闲后把候选检查点写为 A7.3a 的不可变 generation；显式保存期间锁定编辑输入。保存仍由主进程复核磁盘基线并执行 A7.3a 的独占发布。切换阅读/编辑模式不触发保存；clean 保存不改原文字节，changed save 才更新会话基线。
- 写入门槛：dirty 期间，阅读模式必须标明未保存预览，并暂停高亮、便签、标签、重定位和摘要等依赖已落盘摘要的批注写入。renderer 的控件禁用只是反馈，所有批注 mutation IPC 还必须在主进程根据当前会话 dirty 状态拒绝。打开、拖入、重新载入和窗口关闭也必须先处理同一候选，不能静默换掉或丢弃它。
- 恢复决定：草稿和源 backup 只通过 opaque ID 暴露给渲染进程。只有与当前磁盘版本关系为 `recoverable` 的草稿可载入；`conflict` 草稿继续独立保留，不能自动改绑到外部版本。恢复项按精确摘要显式丢弃。正常保存只展示本次返回的精确源 backup，不根据文件名猜测历史先后顺序，也不自动扫描全部 backup。
- 理由：LF 投影符合浏览器文本控件的实际行为，同时由主进程掌握原始格式，可避免 CRLF、BOM 或尾换行产生无关 diff。epoch/revision 阻止迟到消息覆盖新文档或新候选；renderer 与 main 的双层 dirty 门槛确保绕过界面直接调用 preload 也不能把 sidecar 提交到错误的源摘要。
- 未采用方案：本批不引入富文本或语法编辑器依赖，因为首要门槛是证明逐字源码、字节往返和冲突恢复；不把 dirty 限制只放在 React；不让 `textarea` 直接持有 CRLF；不自动载入冲突草稿或按时间猜测 backup。以上方案都会扩大写入面或弱化可证明的版本关系。
- 后果与边界：当前编辑器没有语法着色、编码转换或另存为；混合换行仍只读。保存后的批注现由 ADR-015/A7.4 先迁移可证明的锚点，其余继续进入 A6 审查。Markdown、批注 YAML 与画布 JSON 的联合事务仍由 A8.1 验证。实现、命令和打包版观察结果记录在 `PROGRESS.md`。

## ADR-015：显式源码保存以歧义闭包映射批注锚点

- 日期：2026-09-30；状态：A7.4 已完成并通过 Windows 打包版 E2E。
- 映射决定：输入是保存前与保存后的精确 Markdown 字节和文本视图，不在新全文中搜索第一次出现的 `sourceExact`。核心层独立计算最长公共前缀与后缀，并对重复区域允许的全部等价最小单补丁对齐取并集。这个并集形成保守编辑包络；若边界切在 UTF-16 代理对或 CRLF 中间，则向外扩大不确定区。只有完整位于最早可能编辑之前或最晚可能编辑之后的旧基线锚点才进入自动映射。
- 核验决定：旧锚点先核验 `basisSha256`、UTF-8 半开字节范围、`sourceExact` 和旧阅读范围。包络后的锚点按总 UTF-8 字节差平移，再重建 `prefix`、`suffix` 与 `sectionHint`，并重新核验新字节片段、阅读范围和目标碰撞。通过的记录改用新 `basisSha256` 并更新 `updatedAt`；相交、歧义、无关旧基线、不可渲染或碰撞的记录完整保留旧锚点和时间，形成明确的 mixed-basis sidecar。
- 保存顺序：自动同步只发生在用户显式且真正改变字节的 Markdown 保存。主进程保存前从磁盘重读 sidecar，要求无待处理/不可读批注草稿、顶层 `source.sha256` 等于旧 Markdown 且 sidecar 摘要可用。Markdown 先通过 A7.3a 的 expected-SHA 协议提交；随后 sidecar 以新 Markdown 摘要、保存前 sidecar 摘要和旧 sidecar 源摘要条件写入。Ctrl+S 与窗口关闭时的“保存”调用同一协调函数。
- 零写入与失败合同：普通输入、dirty 阅读预览、模式切换、clean save、Markdown 保存失败和缺失 sidecar 都不写 YAML；缺失 sidecar 不创建空文件。若 Markdown 已提交而 YAML 随后冲突或写入失败，Markdown 仍返回成功，外部 sidecar 不被覆盖，完整映射候选保存为批注恢复草稿并向用户显示部分成功状态。pending 或不可读批注草稿会使自动同步延期。
- 理由：只用一种最长前后缀对齐会在重复删除时武断决定“哪一份文字存活”；对等价对齐取并集可让相关锚点全部保持待定位，同时仍允许全文前插等位置可证明的重复引文安全平移。Markdown 先提交符合源码是内容真相的规则，条件 sidecar 写回则避免把锚点提交到未落盘候选或覆盖已观察到的外部版本。
- 已知边界：当前只从一次保存的最终前后文本推导一个包络。多处远距修改之间的未触碰锚点可能保守进入 A6；以后可由主进程累积并验证逐 revision 编辑范围提高召回率。A2 sidecar 存储在锁内多次复核摘要，但最后一次复核与替换之间仍有不遵锁外部写入的极小竞态窗口；更强发布协议与三文件事务在 A8.1 一并决定。
- 验证：新增 10 项核心测试，覆盖 BOM/CRLF、中文/emoji、重复引文安全平移、半开区间 start/end、上下文与章节线索重建、不可渲染范围、无操作、旧基线、重复删除歧义和无效输入。全套 `npm test` 144/144、`npm run typecheck`、`npm run package` 通过。`tests/e2e/a7-4-packaged.mjs` 在真实打包进程中验证 dirty YAML bytes/mtime 不变、3 条安全锚点迁移、1 条相交记录保留旧基线、无 sidecar 不创建和重启后 3 resolved/1 unresolved；A7.3b、A7.1、A7.2 与 A6 打包版回归同时通过。

## ADR-016：章节结构变换先生成候选并复用源码编辑撤销栈

- 日期：2026-10-01；状态：A7.5 已完成复查与打包版验证；画布与三文件事务留待 A8。
- 决定：章节移动和提升由 `src/core/section-transform.ts` 生成候选，不直接改磁盘。移动完整子树并插入目标末尾；提升把子树放到保留父章节末尾或文档顶层末尾，避免原地改级别捕获相邻章节。重解析核对原章节身份、全部父级、深度、标题内联与正文 AST；首次引用定义和已使用标题片段链接的目标身份必须保持。阅读器和变换器共用标题片段 ID 生成器。
- 安全边界：自身、后代、当前父级、无效索引、六级溢出、归属或链接变化、Setext 转换后内联含义变化明确拒绝。单行 Setext 保留下划线或转 ATX；多行不改级别可移动，需要转换则拒绝。原始 HTML 除独立注释外保守拒绝。边界换行以原换行风格补充并明确预览，不重序列化 AST。
- 交互：源码编辑器提供移动/提升、完整源码预览、取消、过期阻止与一次撤销/重做。只读批注预检 IPC 只接收 epoch 和候选文本，不改变会话、不写文件；从磁盘基线复用 A7.4 并列出待定位引文。dirty 冻结继续生效，保存仍重新核验并使用保守单包络。
- 理由：在卡片画布尚未有稳定 ID 和三文件事务前，先验证最小文本补丁与候选重解析，可以证明移动不重新序列化无关正文，也让撤销与源码编辑共享同一命令边界。把结构操作限制在源码编辑模式避免把视觉拖动误当成文档顺序变化。
- 未采用方案：本批不把结构变换写入独立 JSON，不按标题文本搜索重建来源，也不让普通卡片位置改变 Markdown；这些方案无法在重名标题和外部变化时证明身份或恢复边界。
- 验证：20 项结构核心样本，全套 164/164、类型检查、缓存 Electron ZIP 打包、A7.5/A7.3b/A7.4 打包版通过。A7.5 覆盖预检、取消、过期、窄 IPC、撤销/重做、dirty 零写入、BOM/CRLF 保存、待定位保留与重开；1200/800 px 截图已检查。尚未验证画布投放、结构专用逐范围迁移和三文件恢复。

## ADR-017：画布锚点与三文件恢复先固定为可审计核心合同

- 日期：2026-10-01；状态：A8.1 核心门槛已通过，真实卡片 UI 留待 A8.2。
- 决定：`src/core/canvas-state.ts` 使用 v1 JSON 合同。卡片 ID 独立于标题文本；标题卡片记录已落盘 Markdown 摘要、标题路径/深度、精确标题源码字节范围和直接正文摘要，前言/全文使用虚拟锚点。位置为相对父级的坐标，折叠、箭头端点和视口单独保存。源摘要相同只按精确身份复用；外部编辑只接受唯一标题路径、标题源码和正文摘要匹配，重名或冲突保留旧卡片和箭头并列为待修复。
- 决定：`src/main/document-transaction.ts` 先写三类文件的 immutable before/after 快照和 journal，再在每个目标的独占锁内逐项核对摘要后以独占硬链接发布。每个候选限制大小、严格 UTF-8、重新解析 Markdown/YAML/JSON，并要求新 sidecar 的 Markdown 摘要一致。中断留下可校验的 displaced 原文；显式恢复只能在没有外部冲突或未知锁时 roll-forward，绝不覆盖重建的目标文件。
- 理由：标题名、偏移或 React Flow 节点都不能单独证明同名/重排后的卡片身份；三文件没有跨文件原子 rename，必须先让每一代候选可独立恢复，再把部分发布暴露为可审计状态。快照和 journal 也让应用退出后能列出 prepared/committed/interrupted/conflict，而不是猜测“最新文件”。
- 后果：A8.1 不把事务强行接入卡片 UI；A8.2 通过这些核心函数实现拖动/折叠/连线的普通持久化，结构变换仍使用已核验章节预览。当前不承诺物理断电下目录项原子性，导出和安装包恢复仍需独立验证。
- 验证：11 项 `tests/core/canvas-state.test.ts` 和 5 项 `tests/main/document-transaction.test.ts`，加上全量 180/180、类型检查和缓存 Electron ZIP 打包；覆盖重复标题、外部重排/修改、BOM/CRLF/中文/emoji、虚拟卡片、schema 拒绝、外部重建、锁、中断恢复、伪造 journal 和 sidecar 基线校验。

## ADR-018：卡片模式只持久化画布投影，不把视觉操作解释为 Markdown 结构

- 日期：2026-10-01；状态：A8.2 当前切片已通过打包版验证，导出留待 A8.3。
- 决定：卡片模式由 A8.1 的 `SectionTree`、稳定卡片 ID 和 `CanvasState` 投影到 React Flow。父卡使用相对坐标和真实 `ResizeObserver` 尺寸，ELK 只在初始/显式自动整理时计算布局；拖动、折叠、展开、视口、箭头及标签只写 `*.md.mermarkd.json`。折叠分支的箭头画面上临时投影到最近可见祖先并标记隐藏端点，JSON 端点保持不变。
- 决定：画布 IPC 只接受当前 Markdown 摘要、预期画布摘要和已校验 `CanvasState`；主进程拒绝 dirty 编辑、外部摘要变化、未知字段和并发写入。编辑卡片本节回到源码编辑器，结构拖入仍使用 A7.5 的源码候选预览，不能由普通拖动触发。
- 理由：React Flow 的 `parentId` 不能成为章节真相，视觉边界也不能决定 Markdown 父级；把两者分开才能在重名标题、折叠箭头和外部编辑时保留待修复状态，并确保画布操作不污染 Markdown/YAML。
- 后果：当前卡片模式支持嵌套、真实尺寸、拖动、折叠/展开、箭头管理、搜索、视口、撤销/重做和重开恢复。三文件发布仍通过逐文件锁与 A8.1 journal，未承诺物理断电原子性；结构投放区和导出另行实现。
- 验证：新增 4 项 `tests/core/canvas-scene.test.ts`、2 项 `tests/main/canvas-store.test.ts`、全量 190/190、类型检查、缓存 Electron ZIP 打包；A8.2 打包版验证 4 张嵌套卡片、父卡拖动、撤销/重做、折叠隐藏端点、箭头标签、dirty 主进程守卫、Markdown/YAML 零写入、1200/800/420 px 和重开恢复。

## ADR-019：导出使用独立静态场景并在完整边界上拒绝裁切

- 日期：2026-10-01；状态：A8.3 当前切片已通过核心与 Windows 打包版验证。
- 决定：导出不捕获 React Flow 当前视口，而是由 `CanvasScene` 计算父子卡片绝对坐标、箭头 Bézier 控制点、箭头标记和标签包围范围，再生成受限静态 SVG。标题、正文摘要和子章节数量由当前 Markdown `SectionTree` 派生；用户文本统一 XML 转义。PNG/JPG 使用隐藏 sandbox 窗口的 `capturePage`，PDF 使用同一页面的 `printToPDF`。
- 安全与一致性：preload 必须提供当前 Markdown 摘要；主进程重新核验摘要、章节数量、父级关系、场景字段、背景色、尺寸和当前磁盘源摘要。dirty、并发导出、文档切换和布局写入互斥。输出使用临时文件 `sync` 后改名，不允许覆盖 `.md`、`.annotations.yaml` 或 `.mermarkd.json`。
- 限制：单边最多 12,000 px、总面积最多 40 MP；文本溢出、捕获尺寸不完整和超限均返回错误，不输出被裁切文件。首版 PDF 只生成完整单页，不自动分页或分块；高 DPI、多屏和干净安装环境另行复测。
- 理由：Electron 的 `capturePage` 只保证可见窗口范围，直接截取交互画布会遗漏视口外卡片。静态场景可独立计算完整边界并在写盘前检查结果；超过当前窗口或内存可证明范围时明确失败比生成误导性文件更安全。
- 验证：新增 4 项 `tests/core/canvas-export.test.ts`；全量单测、类型检查和缓存 ZIP 打包通过。`tests/e2e/a8-3-packaged.mjs` 实测 PNG/JPG/PDF、三层嵌套、视口外节点、长中文标签、1 页 PDF、源 Markdown/YAML 不变和 dirty 按钮冻结，输出边界 `1648 × 1198`。

## ADR-020：结构投放只暂存源码，显式保存才提交三文件事务

- 日期：2026-10-01；状态：A8.4 当前切片通过打包验证。
- 结构预览由主进程持有 token 和精确三文件 before/after 候选；确认重新读取全部基线后只进入编辑缓冲区的一条 revision。渲染器把它作为单条源码撤销命令；模式切换保留编辑器历史，dirty 画布只消费内存候选且拒绝写入。
- 批注通过重新核验的结构源码保留范围映射，不搜索同名引文；卡片使用已验证 sectionOrder 保留 ID、折叠、视口与箭头。Setext 重写、旧 basis 或不可靠范围保持待定位。额外编辑无法再使用原结构证明时，从原基线进行保守映射，相关箭头保留待修复。
- 保存由编辑会话统一协调 Ctrl+S、保存按钮与关闭窗口保存：先持久化源码草稿，再核对独立基线，准备并提交 A8.1 的三文件事务。原始/候选快照不自动删除；冲突或部分发布保留恢复证据并停止后续直接写入。批注 pending/unreadable 草稿阻止结构预览及保存。
- 理由：在确认时直接落盘会破坏“确认进入撤销栈、显式保存写文件”的产品合同；单包络映射会丢失可证明的移动批注，按文本匹配又会误贴重复引文。专用范围证明与三文件事务分别解决身份和恢复边界。
- 验证：全量 200 项、类型检查、打包、新 A8.4 和相关旧批次桌面回归通过；P0 的完整事务恢复界面和干净安装验收另行推进。

## ADR-021：事务恢复使用只读核验、显式继续与完成凭据

- 日期：2026-10-01；状态：A8.5 当前切片通过打包验证。
- 决定：恢复入口属于共同外壳；当前文档可枚举未完成事务，源路径缺失时可显式选择同目录 journal。主进程核验受限 journal 与原始/候选快照，持有路径、摘要和一次预览 token；preload 不接受任意目标写入路径。预览只展示源码与三类文件状态，确认才继续 roll-forward。
- 约束：打开未完成事务冻结编辑、批注、画布与导出；恢复拒绝外部冲突和活动/未知锁。dirty 会话仅允许恢复自身已开始的结构事务，其他候选先由现有保存/放弃流程处理。恢复成功重新建立文档会话，不静默拼接不同版本的缓冲区和 sidecar。
- 完成凭据：成功核验三类 after 状态后写绑定 journal 摘要的独占 receipt。快照保留，但带合法 receipt 的历史记录不会在后续正常编辑后触发 pending 门槛。无凭据或损坏凭据保持保守检查；候选与当前文件不匹配仍拒绝恢复。
- 理由：仅比较历史 after 摘要，会把正常后续编辑当成旧事务冲突；只允许先打开 `.md` 再恢复则无法处理原路径已经被 displacement 移走的中断。独立完成证据与 journal 文件选择解决这两个实际恢复缺口。
- 验证：202 项全量测试、类型检查、打包、A8.5 多端与缺失/部分/冲突/锁/同会话故障注入验收，以及相关桌面回归通过；最新 Windows Setup 已生成。未承诺物理断电原子性或干净环境安装验收。

## ADR-022：用三份文档分离当前状态、开发时间线与稳定决策

- 日期：2026-10-01；状态：已采用。
- 决定：`docs/PROGRESS.md` 只描述当前阶段、验证门槛和下一批入口；`docs/DEVELOPMENT_LOG.md` 按批次追加用户反馈、目标、设计决定、修改文件、实际命令、产物、失败与下一步；`docs/DECISIONS.md` 只记录需要跨批次保持稳定的架构、数据、持久化和安全合同。
- 理由：把状态、过程和长期决策混写会让 GitHub 上的开发历程难以检索，也容易把一次测量或暂定阈值误读成长期产品承诺。三份文档各自单一职责，既保留过程证据，又不让当前状态页无限增长。
- 流程：每批完成后先重新检查代码、数据边界、测试和打包结果，再更新 `PROGRESS.md` 与 `DEVELOPMENT_LOG.md`；有稳定架构变化时追加本文件。日志必须保留实际命令、范围、失败原因和未覆盖项；没有 `.git` 元数据时明确标出无法提供 commit/diff/PR 证据，恢复后补充链接。
- 后果：后续 B0–B6 每批都有可读的时间线入口；纯规划批次也必须记录未实施内容和下一步，不得把规划写成已完成能力。当前流程不会自动生成 Git 提交，也不替代 GitHub 的提交历史。

## ADR-023：B0 先固定 v2 画布投影和共享编辑事务的核心合同

- 日期：2026-10-01；状态：B0 核心切片已通过；UI 投影和阅读富文本编辑留待后续批次。
- 决定：v1 画布状态可以通过 `src/core/canvas-state-v2.ts` 只在内存迁移到 v2。v2 卡片把原 `collapsed` 明确拆为 `descendantsCollapsed`，增加 `contentPosition` 和 `bodyDisplay`（`hidden` / `preview` / `full`）；原 `position` 仍表示由 Markdown 层级派生的章节组位置。迁移默认 `bodyDisplay: preview`，不把旧摘要宣称为全文，打开旧 JSON 不自动写盘。
- 决定：正文编辑先使用无 UI 依赖的 `MarkdownEditSession` 事务模型。每次局部替换必须带 `expectedRevision`，拒绝过期选区和 UTF-16 代理对中间边界；事务保留 baseline、当前快照、past/future，并支持撤销、重做和新编辑清理重做分支。它操作现有 Markdown 缓冲区，不从渲染 DOM 重建全文。
- 理由：先把数据身份、双折叠语义和共享撤销边界做成可测试核心，能在不破坏现有 v1 打包应用的情况下验证中文、emoji、BOM/CRLF 和局部修改。把 v2 直接接入 React Flow 或直接安装富文本编辑器会同时扩大持久化和渲染风险。
- 未采用方案：本批不把 v2 状态替换现有 v1 IPC，不在打开时自动升级磁盘 JSON，不引入 CodeMirror/ProseMirror，不把批注高亮写进 Markdown，也不从整页 HTML 反向生成源码。
- 验证：新增 `tests/core/canvas-state-v2.test.ts` 5 项和 `tests/core/markdown-edit-transaction.test.ts` 3 项；全量单测 `210/210`、`npm.cmd run typecheck`、`npm.cmd run package` 通过。安装版 UI 和真实阅读富文本编辑尚未由本 ADR 宣称通过。

## ADR-024：B1 工作区外壳保持侧栏瞬时、最近文件主进程持有

- 日期：2026-10-02；状态：B1 工作区外壳切片已通过打包版验证。
- 决定：最近文档偏好使用 `src/core/recent-documents.ts` 的严格模型，只保存绝对路径和 Unix 毫秒时间；主进程在 `app.getPath('userData')` 下读取、过滤实际存在的 `.md` 文件并写回，preload 只提供列出、打开和移除命令。最近列表不能成为 Markdown、批注 YAML 或画布 JSON 的身份真相。
- 决定：打开文档后的顶栏使用单行模式导航和最小状态，路径、编码和完整文件状态放入瞬时文档信息侧栏；左侧最近文档栏、右侧信息栏和焦点模式不写内容文件。侧栏互斥打开，避免窄屏同时覆盖正文。
- 决定：B1 新建先通过原生保存对话框明确目标路径，再以独占创建方式生成空 Markdown 并进入 `DocumentSession`；不在本批引入空路径虚拟文档，以免既有保存、批注和三文件事务把临时路径当成真实文件。无路径新建与首次保存另存为另开 B1.1 合同。
