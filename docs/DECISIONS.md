# MerMarkd 技术决策记录

本文件记录会影响后续实现或用户数据的决定。P0 原型未完成前，标记为“暂定”的决定仍需以实测结果复核。

## ADR-001：Windows 首发，Electron Forge + React/TypeScript

- 日期：2026-09-17；状态：P0 本机打包与安装验收通过；升级仍需重复验收。
- 决定：先用 Electron Forge、React、TypeScript 开发 Windows 桌面版，npm 管理依赖并提交锁文件。优先试用 Forge Vite 模板且固定版本。
- 理由：Electron 提供明确的 PDF 打印和页面捕获 API；本机 Node/npm/Git 可用，不依赖 Rust。Forge 可生成 Windows 安装包。
- 风险与替代：Forge Vite 插件目前标为实验性。P0 若打包或安装不稳定，在业务代码较少时换成 Forge Webpack 插件；不更换文档核心模型。
- 验证：启动、类型检查、package、Windows Setup.exe 安装与运行均已通过。本机卸载有 Squirrel 残留、启动有缓存权限警告，须在干净环境复测。首次 Electron 下载超时，使用镜像后完成。

## ADR-002：Markdown 与伴随画布文件分离

- 日期：2026-09-17；状态：暂定，待恢复实验。
- 决定：`.md` 保存正文和标题；同目录 `*.md.mermarkd.json` 保存卡片 ID、坐标、折叠和箭头。批注采用独立的 `*.md.annotations.yaml`，见 ADR-006。两类 sidecar 均绑定已落盘 `.md` 摘要；未保存的相关状态进入恢复草稿。
- 理由：普通 Markdown 文件保持可独立使用，视图操作不改写正文。
- 风险与替代：三文件无法原子同时提交。保存采用基线摘要校验、事务日志、依次替换与恢复；P0 若不能可靠恢复，再评估将布局存入独立项目容器的方案。
- 验证：模拟每个写入中断点、双实例与外部修改，重开后无正文、批注或箭头丢失。

## ADR-003：保守执行章节结构变更

- 日期：2026-09-17；状态：已定产品原则，技术细节待 P0 验证。
- 决定：只在用户明确改变卡片容纳关系、预览确认后生成最小原文补丁。候选全文必须重新解析与校验；不安全场景阻止操作。多行 Setext 需转成 ATX 时首版不自动执行。
- 理由：Markdown 的相邻块、引用定义与标题语法会让简单字符串切片产生隐性语义变化。
- 验证：固定样本的移动/撤销字节往返、父子树与链接语义校验。

## ADR-004：独立导出场景

- 日期：2026-09-17；状态：暂定，待 P0 导出原型。
- 决定：交互画布与导出渲染器共享场景数据，不直接截图 React Flow DOM。导出场景使用 HTML 卡片和 SVG 箭头；PDF 先分页再打印；位图逐块捕获。Sharp 只在安装包中验证通过后用于单张拼接。
- 理由：视口裁剪、嵌套 DOM 与页面尺寸使直接截图无法保证完整导出。
- 验证：中文、图片、长卡片、跨页箭头、视口外节点、8k 以上场景与安装包内输出。

## ADR-005：阅读渲染与资源权限边界

- 日期：2026-09-17；状态：最小阅读切片已实测，后续卡片正文复用时再验收。
- 决定：阅读界面使用 `react-markdown`、GFM 与 YAML frontmatter 插件；标题目录仍来自 `src/core` 的章节树。默认跳过原始 HTML。用户可通过文件选择器或右上角明确的拖放区域打开单个本地 `.md`；拖放文件的真实路径由 preload 获取，主进程重新校验后按相同的只读流程载入。相对图片限在当前文档目录，外链仅允许 `http`、`https`、`mailto` 并交给系统浏览器。
- 理由：Markdown 正文可能包含不可信链接或 HTML，需要让正文显示与本地文件权限分离，同时保持阅读无写入路径。
- 验证：UTF-8/BOM、危险协议、目录越界测试通过；打包版打开正常样本与危险样本，本地图片显示，原始 HTML 未产生可执行 DOM，源文件 SHA-256 不变。

## ADR-006：批注使用独立 YAML sidecar 与保守源码锚点

- 日期：2026-09-17；状态：产品决定；A1 单块源码映射原型已验证，YAML 格式、持久化与重定位仍待 P0 验证。
- 决定：每份 `example.md` 对应同目录 `example.md.annotations.yaml`；画布 JSON 保持独立。高亮与便签共享稳定 ID；可选一个标签。每个锚点持久化为原始 UTF-8 字节半开范围、该范围所属版本的 SHA-256、原文片段、前后文、可见引文和章节线索。屏幕位置只在渲染时计算；摘要不符的旧锚点先冻结为待定位，不能按旧偏移显示。
- 理由：Markdown 不被阅读标记污染；YAML 可随原文携带、由 Git 审阅，独立文件减少画布操作引起的无关差异。源码位置与上下文结合比 DOM 像素或纯文本搜索更可靠。
- 风险与替代：YAML 不能保证 Git 自动合并；源码与可见文字在格式标记处不一一对应，UTF-16/UTF-8/BOM 也需转换。先支持可精确映射的单块选区；不唯一时保留便签并进入待定位，不自动错贴。若 YAML 往返造成大范围 diff，调整序列化策略而不改 Markdown 存储原则。
- 验证：重复选文、加粗/链接、中文/emoji、BOM/CRLF、外部编辑、删除/复制/移动章节、非法 YAML、双实例与中断写入样本；保存后 `.md` 原始字节摘要不变。

## ADR-007：混排使用语义布局，阅读装饰保持克制

- 日期：2026-09-17；状态：产品与排版原则，待跨缩放视觉验收。
- 决定：GFM 表格保留 `<table>` 单元格布局并在外层滚动；列表使用原生标记和固定缩进；代码块明确 tab 宽度与横向滚动。批注在边栏展示，低饱和度高亮不改变字宽和行高。默认不为全角/半角对齐改写 Markdown。
- 理由：不同字体、回退字形、emoji 和缩放下，字符宽度没有可靠的固定倍数；插入空格既会破坏原文，也不能保证阅读视图对齐。
- 验证：中英文、全半角标点、长 URL、emoji/组合字符、两位数及嵌套列表在窄窗口与 100%/125%/150% 缩放下无错列、遮挡或裁切，原文件摘要不变。
