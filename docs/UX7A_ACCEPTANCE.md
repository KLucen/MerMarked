## 用户可见变化

| Before | After | Why |
| --- | --- | --- |
| 阅读中需要尝试输入后，才能知道当前内容是否允许直接修改 | 聚焦或选择当前内容后，显示一份当前编辑方式提示，并提供“在源码中编辑此处” | 在输入前说明边界，减少试错，保持阅读正文简洁 |
| 列表、表格、代码等受限内容缺少靠近当前任务的源码入口 | 当前内容提示共用一条源码定位路径；可定位的选区仍有原选区入口 | 用户可从正在处理的内容继续，不需要在整份源码中重新寻找 |
| 原生正文块提交返回 false 时，恢复原 DOM 可能没有保留失败文字 | 返回 false 与异常均留下可查看、复制、放弃及继续源码的未应用输入 | 失败不能悄悄丢失用户刚输入的文字 |
| 长源码行只能横向滚动，显示方式固定 | “显示与快捷键”中可启用软换行，默认关闭 | 适应窄窗口，同时保留文件原始换行和完整源码 |
| 行列状态可见，但没有直接转到行入口 | 工具栏与 Ctrl+G 打开行号输入；合法行号精确定位，非法行号说明范围 | 让用户按行号定位，并在出错时保持原光标 |
| 常用源码快捷键需要自行记忆 | 显示选项展开后提供简短保存、撤销、查找及行定位键表 | 把帮助放在需要时打开的位置，避免常驻占用阅读空间 |

## 验收例子与边界

1. 点击或聚焦普通段落，当前提示说明同一可证明文字片段内的编辑能力；跨强调、链接、换行以及受限内容引导至源码。提示采用不占正文布局的固定面板，不因指针按下时显示提示而移动原目标；只读/忙状态明确说明源码查看。提示不改变原生选区，不暴露字节偏移或原始锚点诊断。
2. 从普通段落、强调/链接、列表、表格或代码进入源码时，使用当前文档的已知源码范围。转换考虑首个 BOM 和 CRLF 到 LF 的完整编辑模型，不猜测字符串的首次匹配位置。文档或正文变化后不沿用旧目标。
3. 阅读块输入被拒或抛错时，未应用文字可恢复；进入源码只定位并保留该文字，不自动把它拼接到正文。旧文档的异步反馈不能写入新文档提示。
4. Ctrl+G 或“转到行”打开行号输入并获得焦点。输入 1 到当前总行数的整数后，Enter 跳到该行起点并回到源码；0、超限值、小数或非数字显示范围错误，不改变源码和光标。Escape 关闭并恢复源码焦点；组合输入期间不抢先处理 Escape 或提交。
5. 软换行仅重配 CodeMirror 显示扩展。源码全文、逻辑行数、选区、撤销历史和 `.md` 字节保持；关闭软换行可恢复横向阅读。行定位使用 CodeMirror 的 LF 文档行模型和 UTF-16 起点，不按视觉折行计数。
6. 模式或文档变化关闭临时行定位与帮助面板；软换行仅在内存中保留，不写 Markdown、批注 YAML、画布 JSON 或新偏好文件。保存恢复模态阻挡 Ctrl+G，不能打开后方行定位框。

本批不增加依赖、持久化 schema 或 preload IPC，不替换编辑器，不新增第二套历史，不执行全文 DOM 反序列化。正文、批注和画布仍分别版本化；模式切换、提示、定位和显示选项不写三个内容文件，显式保存继续既有冲突与事务路径。

## 失败记录

B 构建完成后的首次窗口专项在源码目标偏移应为当前段落、实际为 0 时失败。C 诊断确认：提示出现占据正文布局，把指针下方段落从 y=196 移到 y=263，pointerup 落到标题，导致目标被替换为标题起点。产品改为底部固定提示面板，避免占用正文布局；D 重包后的段落目标偏移断言通过，保留严格目标与偏移检查，没有放宽测试规避问题。

随后专项行定位 Enter 未触发表单提交，测试 helper 原先只发 keyDown/keyUp，缺少字符事件；已由 E2E agent 修正，最终专项尚待完整运行。上述失败和 C 诊断由主线程保留原日志；后续最终结果需另记，不覆盖旧失败。

E 轮在运行时发现测试关闭反馈的 evaluate 表达式引号错误，修复后 F 完整专项通过。G 补充可关闭的浮动提示，最终类型检查、315 单测、make 后 27 套窗口及真实 Vite 完整专项全部通过。全部原失败保留，不以修改断言来避开目标、偏移或文件边界检查。
