# UX6B：文档流程与保存语义

> 2026-11-06，第 4 批 UX6B 本机工程退出条件通过。基于已合并 PERF3 / [PR #16](https://github.com/KLucen/MerMarked/pull/16)，main `19e1402`。最终包 G 的类型检查、315 单测、26 套打包窗口、真实 Vite 完整流程及 Squirrel make 已通过；交付状态见 [PROGRESS.md](PROGRESS.md)。P0 与设备验收仍独立未完成。

## 验收例子

1. 已打开文档时，从文档菜单或 `Ctrl+N` 新建未命名文档，直接进入源码并聚焦输入。`Ctrl+O` 打开、`Ctrl+W` 关闭当前文档；关闭文档返回开始页，保留应用窗口。开始页只有一组打开与新建主操作。
2. 正文未保存时，打开、新建、关闭、最近文件、拖入或重新载入统一先处理 UX6A 的本地未提交输入，再询问“保存并继续 / 放弃正文修改并继续 / 取消”。正文保存成功后继续原操作，不要求用户再次寻找入口。
3. 取消正文离开提示时停留原文档、保留完整缓冲区且不写三个内容文件。首次保存取消、磁盘冲突或其他保存失败时保留原操作和当前内容，显示继续或取消原操作的入口；重试仍核验当前输入和文档身份。
4. 新便签及标签、编辑已有便签独立接受离开保护。选择返回或取消保留文字、标签与焦点；允许放弃后又取消文件选择，仍保留本地表单。只有文档替换成功才清除表单，不把“保存正文”当成提交批注。
5. 顶栏明确写“保存正文”，画布按钮明确写“保存视图”。显式保存正文维持 BOM、CRLF、无尾换行和锚点同步合同；保存视图只处理画布 JSON，不改 Markdown 或批注 YAML。
6. 420 与 800 CSS px 布局下，文档菜单的新建、打开、关闭入口可见且可点击；首次保存后可关闭并重新打开相同正文。正常成功提示约 5 秒后消退，错误与待继续操作保持可处理。

## 文件与交互边界

- 新建只创建内存文档；第一次显式保存才选择文件位置。不增加已有文档的跨路径另存为，也不改为正文自动保存。
- 打开、关闭文档、模式切换、取消离开和取消文件选择本身不写 Markdown、批注 YAML 或画布 JSON。明确选择保存才调用原正文保存服务，已有 sidecar 的必要锚点同步仍走原核验与事务。
- 本地表单的放弃许可不提前清空表单。来源文档、编辑缓冲区或输入在等待期间变化时，旧许可不能继续操作；保存失败不替换文档。
- `src/core/document-departure.ts` 只协调当前缓冲区的许可结果，不访问 Electron、文件系统或 UI。新 IPC 仅为固定选择确认与关闭所属窗口的当前文档，不接收任意路径、源码或摘要。
- 主进程关闭文档独立拒绝 dirty 正文或进行中的文件写入；窗口关闭继续复用 UX6A 的 renderer 协调及既有主进程保存流程。
- Windows 显式保留原生文件、编辑、视图菜单及窗口最小化/缩放；“关闭窗口”调用原有 `window.close()`，不设置 role 或 accelerator，避免 Electron 默认窗口关闭命令提前消耗 `Ctrl+W`。`Ctrl+W` 留给受保护的关闭文档命令，`Alt+F4` 与系统关闭按钮仍走原窗口关闭保护。
- 取消后恢复焦点时，已被离开锁关闭的文档弹出面板回到其触发按钮，表单返回处理继续回到原输入位置。
- 新建的源码焦点绑定逻辑文档，等离开保护解锁且编辑缓冲区就绪后发出请求。保存恢复模态拦截 Ctrl+N/W/O，不能从模态内替换或关闭后方文档。

## 失败记录与限制

多行源码沿用原型已确认的真实剪贴板粘贴路径，避免 CDP `Input.insertText` 的空行问题。B 轮正文键盘选区准备失败；C 轮追加输入落在开头，已补入源码焦点与精确末尾选区核验；D 轮真实拖选仍无法可靠建立预期选区，便签场景改为 test-only DOM Range 仅建立选区目标，不把这项测试修正描述为真实拖选通过。原 `ux6b-b-flow.log`、`ux6b-c-flow.log`、`ux6b-d-flow.log` 保留，最终 G 完整专项在独立日志通过。

包 B 的原生菜单探针确认 Electron 默认窗口 Close 绑定 `CommandOrControl+W`，仅向页面注入 CDP 快捷键不足以发现冲突。Windows 改为显式关闭窗口菜单项且不设置 role/accelerator。E 轮类型检查发现 `MenuItemConstructorOptions` 不接受 `accelerator: null`，改为无 role 的显式点击回调，避免 role 默认 accelerator；原失败记录保留。F 类型、生产构建、全部窗口及 UX6B 专项通过。

首轮真实 Vite 的 Ctrl+N 焦点断言失败：请求可能在离开锁使工作区 inert 时被消耗。G 将新建焦点绑定逻辑文档，等解锁及编辑器就绪再发请求；复测完整通过。独立审查另发现新增快捷键会穿透恢复模态，已加入原拦截列表并补开始页/已打开文档两种窗口证明。最终 G 在 make 后重新运行全部 26 套窗口，并从强制冷优化的 Vite 再跑完整专项通过；所有原失败保留。
