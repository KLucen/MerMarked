# MerMarkd 开发流程与工程规则（v3）

> 2026-09-17，模式边界更新于 2026-09-24。适用于从技术原型到可下载安装的 Windows 首版。当前按单人开发估算，优先做可运行的纵向切片；本文件规定实施方式，不替代[产品与架构方案](PRODUCT_ARCHITECTURE.md)和[三模式职责](MODE_BOUNDARIES.md)。

## 1. 目标与约束

交付目标是用户能安装、打开本地 Markdown，在阅读模式高亮与批注并按标签整理，在编辑/阅读/卡片三模式工作、保存、导出完整画布的 Windows 软件。项目分阶段完成，每个阶段结束时必须保持可启动、可回退。首版只处理单个本地 `.md`；遇到不支持的输入，要明确提示，不能改坏原文件或静默丢掉批注与画布关系。

开发决策以用户最新要求为准；产品语义见 `PRODUCT_ARCHITECTURE.md`，具体技术变化记录在 `docs/DECISIONS.md`。对未明确的普通实现细节直接做可逆决定并记录，不把常规开发工作停在反复确认上。凡改变 Markdown 文件规则、首发平台或导出承诺的决定，先形成可审查的原型与影响说明。

## 2. 阶段验收与批次顺序

| 阶段 | 主要能力 | 阶段完成证据 |
| --- | --- | --- |
| P0 可行性 | 已完成桌面壳、最小阅读、受限单块选区映射和批注 YAML 保存原型；继续验证章节最小文本补丁、三文件恢复、嵌套卡片与 PDF/JPG 整图导出 | 含中英文/emoji/BOM/CRLF 的锚点不误贴；关键路径没有未解释的数据损坏、错位或裁切 |
| P1 文档与阅读产出 | 已完成混排、阅读高亮、便签标签、重定位和摘要；继续收口无源码语法的阅读体验、即时选择反馈、纯源码编辑/保存及跨模式定位 | 阅读不泄露受支持结构的源码语法，编辑不渲染正文；高亮/批注只改 YAML；UTF-8/BOM/CRLF 往返；外部冲突不覆盖 |
| P2 卡片基础 | 标题树、初始布局、拖动位置、展开/收起、伴随数据 | 关闭重开能恢复画布；拖动、折叠、缩放不改 `.md` 摘要 |
| P3 结构与关系 | 用户箭头、结构拖入预览、标题级别调整、撤销、ID 修复 | 边界样本全部通过；一次操作可完整撤销；不确定的连线不错误重接 |
| P4 导出与质量 | PDF/JPG/PNG、分页/分块、性能、键盘操作 | 视口外内容不裁切；中文字体、本地图片、长卡片和跨页箭头有确定行为 |
| P5 发布 | Windows 安装包、签名条件检查、安装/卸载、版本与发布说明 | 在没有开发工具的干净 Windows 环境完成安装、打开、保存、导出和卸载 |

阶段是能力验收清单，具体切片可以交错推进；P0 的章节移动、画布和导出门槛未全过时，可以在锚点与 YAML 保存原型通过后交付小型阅读批注界面，但**不能宣称 P0 或 P1 整体完成**。每批保持可运行、可回退。第一个测试安装包已在 P0 生成。原型验证失败时，先缩小输入或替换局部实现；只有数据模型或核心需求不可达时才整体换栈。

### 从当前进度开始的逐批路线

每批仅实现表中范围，结束时交付可运行程序或可执行原型、验收结果、剩余限制和下一批建议；**告知用户并等待实际试用反馈后才开始下一批**。用户可根据反馈调整顺序；后面批次的细项不是本轮开发授权。

| 批次 | 本批交付 | 本批验收与文件边界 |
| --- | --- | --- |
| A1（已完成）选区锚点原型 | 从阅读 DOM 的单块选文精确反算 `.md` 原始 UTF-8 字节范围；展示可检查的探针结果，不写 sidecar | 普通文本、重复文本、加粗、链接、中文、emoji、BOM、CRLF 样本正确；不支持的选区明确拒绝；`.md` 摘要不变 |
| A2（已完成原型）YAML 持久化 | 定稿 `*.md.annotations.yaml` schema、受限解析、原子写入、重开与磁盘冲突检测；只提供测试锚点保存入口 | 单条新增/修改仅产生相关 YAML diff；非法或未知版本不覆盖；只读写入失败有待保存草稿；源摘要不符的旧锚点冻结为待定位；`.md` 摘要不变。完整跨文件恢复待 A8.1 的最小画布模型就绪后验证 |
| A3（已完成）混排排版 | 语义表格滚动容器、列表/任务框缩进、代码块 tab 与窄窗口布局 | 中英文、全半角标点、emoji、组合字符、长 URL、嵌套列表在实际 Electron 100%/125%/150% 缩放下无错列或整页裁切；不重写 Markdown |
| A4（已完成）高亮交互 | 少量柔和颜色、选区高亮、改色/删除、重开恢复 | 高亮只写 YAML；原文不变；重叠标记可辨识，文字对比度和高对比模式可用，键盘可操作；源摘要不符时旧锚点只显示待定位，不错贴 |
| A5（已完成）便签与标签 | 选文后新增/编辑/删除便签，在创建时选择/新建一个标签或无标签；边栏与窄屏抽屉 | 多便签不遮挡正文，重开仍定位；按标签筛选与跳回原文有效；原文不变 |
| A6（已完成）重定位与阅读摘要 | 外部编辑后检测严格唯一候选并由用户显式应用；删除、重复、上下文变化和碰撞保持待定位；支持人工重选；按当前标签筛选复制按章节组织的 Markdown 摘要 | 删除、复制、移动及同名章节样本不误贴；人工重选保留记录身份与内容；摘要包含引文/标签/便签并把待定位内容单列，只写剪贴板；`.md` 不变，sidecar 冲突不覆盖 |
| A7.1 模式导航外壳与阅读交互收口 | 共享 Shell 接管打开/拖入和已有文件状态；拆分阅读视图；移除源码诊断和 `Hn`；即时选区与滚动章节反馈；未开放入口保持禁用；不新增主动文件监视 | 被动选择、滚动和入口浏览不写或新建三类内容文件；选区不跨文档复用；模式/章节/批注有非纯颜色状态；A4–A6 门槛回归 |
| A7.2 阅读方言与查找收口 | CommonMark+GFM+frontmatter 语义 fixture、原始 HTML 允许列表/占位、已知扩展提示、可见正文查找 | 支持结构不泄露源码语法；危险 HTML 不执行；不可精确映射的派生文字不能批注；未知方言不被误报为已支持 |
| A7.3a 安全保存与单文档草稿原型 | 在 core/main 验证 Markdown 字节往返、expected SHA、原子替换、外部冲突和单文件崩溃草稿；不开放编辑 UI | 无操作保存摘要不变；BOM/CRLF/无尾换行保留；冲突不覆盖；草稿可恢复或明确丢弃 |
| A7.3b 纯源码编辑模式 | 完整源码、不渲染；dirty、查找替换、撤销重做、行列、显式保存和未保存预览限制 | 所有语法字符可编辑；状态栏报告 BOM/换行；阅读不能改正文；dirty 时不把 sidecar 或画布写到错误基线 |
| A7.4 编辑补丁到批注映射 | 只迁移能够证明的批注锚点，其余进入 A6 审查 | 重复文本不误贴；删除和歧义保留内容；不依赖尚未实现的卡片 ID |
| A7.5 章节源码变换原型 | 章节移动、级别调整、差异预览、候选重解析和撤销 | 危险变换拒绝；移动与撤销保留非目标字节和批注内容 |
| A8.1 画布数据与恢复门槛 | 固定最小画布 schema 和稳定卡片 ID；用 JSON fixture 验证 Markdown、YAML、JSON 中断恢复 | 重名章节不误连；每个中断点可恢复或明确冲突；不得伪装为同一基线 |
| A8.2 嵌套画布与关系持久化 | 三层嵌套卡片、拖动、折叠、全部展开/收起、箭头、布局 JSON 与重开恢复 | 非结构画布操作不改 `.md`；重开恢复坐标、折叠与关系；重名标题不误连 |
| A8.3 独立全图导出 | 专用导出场景、PDF/JPG/PNG、分页/分块和尺寸限制 | 视口外节点、中文、长卡片、箭头及标签不裁切；超限明确报告而非截断 |

A1–A6 保持历史编号。2026-09-24 的模式审查把后续工作拆成更小门槛：先完成阅读交互与方言合同，再证明 Markdown 保存，随后开放源码编辑、锚点映射和章节变换；画布 schema 存在后才验证三文件事务。每批若触及前置数据风险，先收缩交付并重新验收，不把未验证能力标为完成。

## 3. 每个切片的固定流程

1. **先写验收例子。** 给出用户操作、预期文件变化、预期画面或导出结果；结构编辑必须包含操作前后 Markdown 样本。
2. **确定边界。** 标记它改的是 `.md`、批注 YAML、画布 JSON、应用本地状态还是导出文件。批注的屏幕位置和卡片可视状态不能成为 Markdown 的内容来源。
3. **实现最小闭环。** `src/core` 的源文本/锚点逻辑先于界面事件；主进程文件能力通过类型化的最小 IPC 提供；界面只调用明确命令。正文选区必须能反查原始字节范围才允许持久化。
4. **验证风险。** 有数据损坏可能的变换写单元与往返样本；交互用集成测试；导出用真实渲染和视觉检查；安装包做干净环境冒烟测试。纯样式等低风险改动不机械增加测试。
5. **更新状态。** 在 `docs/PROGRESS.md` 记录完成、验证命令、未解决问题和下一切片。重大选型变化写 `docs/DECISIONS.md`，说明替代方案和后果。
6. **保持可运行。** 提交前至少完成类型检查、相关测试和打包构建；无法运行的中间实现必须明确标记，不当作已完成阶段。

## 4. 不可破坏的工程不变量

| 不变量 | 如何验证 |
| --- | --- |
| 阅读模式对支持结构只显示语义结果，编辑模式显示完整源码且不渲染 | 同一 fixture 比较阅读 DOM 与编辑缓冲区；阅读中不出现结构标记或源码诊断；编辑缓冲区包含完整解码源码且所有 Markdown 语法字符可编辑，BOM、换行类型与尾换行由状态栏和字节往返验证 |
| 模式切换本身不写任何内容文件 | 切换前后比较 `.md`、批注 YAML 与画布 JSON 摘要；只允许更新应用内偏好 |
| 无操作保存保持 Markdown 原始字节一致 | 覆盖 BOM、LF/CRLF、无尾换行和 Unicode 样本，保存前后比较 SHA-256 |
| 普通卡片拖动、缩放、折叠、连线、导出不改 `.md` | 操作前后对原文件计算摘要；用实际磁盘文件验证 |
| 高亮、批注、标签不改 `.md` | 创建/改色/编辑/删除前后对原始字节计算 SHA-256；只允许批注 YAML 变化 |
| 批注不误贴到相同文字 | 源码字节范围、选文与上下文同时核验；外部改动仅唯一匹配自动恢复，歧义列为待定位 |
| 结构拖入只移动完整章节子树并调整适用标题；不重排其他正文 | 对原文字段做局部补丁；移动后重新解析并比较非目标块；不安全时拒绝操作 |
| 三类持久文件写入可恢复 | 写前核对各自磁盘版本；临时文件写入并替换；跨文件变更有恢复事务 |
| 同一操作可撤销 | 文本、批注与画布补丁按涉及范围作为一个命令事务进撤销栈 |
| 卡片与箭头不误连到重名章节 | 稳定 ID 与保守匹配；歧义时进入待修复状态 |
| 每份 sidecar 和记录如实标明自身基线 | sidecar 记录已落盘原文摘要，每条批注保留 `basisSha256`；允许合法过期或混合基线，但不能把旧范围或未保存结构伪装为当前版本 |
| 混排不靠补空格或改字符修正 | 表格/列表用语义布局；源码与阅读前后摘要相同，缩放和窄屏视觉验收 |
| 导出不静默裁切 | 根据完整图边界计算页/块；超限报出尺寸，分页或多图输出；测试视口外卡片 |

## 5. 代码与安全边界

- TypeScript 使用严格类型；文档解析、章节树、选区/源码映射、批注锚点、结构变换、ID 对齐属于无 UI 依赖的 `src/core`。React Flow、Electron 对象不进入核心领域类型。
- 文件 I/O、打印和图片编码留在 Electron 主进程；渲染进程启用隔离与 sandbox，禁用 Node 集成。preload 只暴露经过路径和参数校验的打开、sidecar 保存、导出接口；批注路径由所选 `.md` 派生，不接收任意写入路径。
- Markdown 阅读和卡片正文使用同一受控渲染管线；不执行原始 HTML 或脚本。网络资源和外链打开必须经过明确的协议与路径策略。
- 编辑模式只使用源码编辑器，不复用阅读渲染组件；阅读选区工具和批注侧栏不得挂入源码编辑器。模式视图共享 `DocumentSession` 和章节位置，不各自保存正文副本。
- 批注 YAML 使用受限 schema、大小/深度/别名限制和严格校验；未知版本只读。批注正文与标签均作为文本渲染，不执行 HTML。
- 所有文件写入保留原编码/BOM/换行策略。首版对不支持编码只读并提示转换；不能猜测编码后覆盖。
- UI 状态、内容状态、磁盘状态分别管理。用户能看出“Markdown 未保存”“批注未保存/待定位”“画布布局未保存”和“导出中”状态。
- 依赖固定版本并提交锁文件。引入原生模块前先跑安装包验证，避免开发环境可用而发布包缺模块。
- 不把绝对用户路径、Markdown 正文或私有导出内容写入遥测。错误日志只保留必要诊断信息；默认离线运行。

## 6. 验证样本与质量门槛

P0 起建立小型文档样本集，至少覆盖：空文件、无标题、前言、同名标题、跳级标题、六级标题、Setext、CRLF、BOM、代码围栏中的 `#`、引用/列表中的标题、GFM 表格、中文、相对图片、长章节、外部文件改动。模式样本要用同一份文件验证阅读 DOM 不泄露结构语法、编辑缓冲区包含完整源码、模式切换保持当前章节且不写文件；编辑保存样本覆盖 BOM、LF/CRLF、无尾换行、无操作保存、dirty 预览和外部冲突。新增批注样本必须覆盖重复选文、加粗/链接/转义/实体、跨节点选区、emoji/组合字符、BOM/CRLF 的 UTF-16↔UTF-8 换算、选文删除/复制/重排、只读目录、YAML 冲突和损坏。混排样本须覆盖中英文与全半角标点、两位数列表、嵌套任务列表、长 URL、表格对齐、代码 tab、320 CSS px 模拟视口、800×600 实际窗口、200% 缩放和高对比模式。结构操作增加“移动到自身/后代/当前父卡”“跨越六级”“移动后相邻块解析变化”及“移动后批注重定位”样本。

测试分层：`core` 样本测试保证语义、选区锚点、YAML 往返、源码保存和原文摘要；UI 测试覆盖即时选区状态、滚动章节、模式切换、高亮、便签/标签、目录、投放区、确认/取消、展开/收起和连线；视觉检查覆盖阅读语法隐藏、混排表格/列表、选区操作条与便签不遮挡；导出测试检查整图边界、页数、可读性和文件打开；桌面冒烟测试检查安装、启动、打开、保存、导出与卸载。性能预算先作为目标而非承诺，用 P0 实测确定上限。

## 7. 版本与发布规则

采用 Git 与小步提交；发布版本从测试安装包开始标注版本号。P0 安装包可以未签名，仅供本机验证。公开分发前再完成签名、许可证清单、发布说明和干净机器测试；签名证书与发布渠道属于发布阶段的外部依赖，不阻碍前期实现与本地安装包验证。

阶段完成的定义是**能从干净检出按文档构建并通过对应验收**，而不是代码已写完。若验证门槛未过，`docs/PROGRESS.md` 如实记录限制和下一步修复，不提前宣称完成。
