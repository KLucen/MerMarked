# QA5 · 阅读组合输入的尾随提交与保存保护

2026-11-20开始，2026-11-21完成本机软件专项验证。基于已合并PR #28 / main `5ea768f`，分支 `codex/qa5-reader-composition`。最终C运行时 `653bff5`，证据见 [QA5_EVIDENCE.json](QA5_EVIDENCE.json)；QA1 / P0仍未整体退出。

## 验收例子与边界

1. 原文 `# 输入测试\r\n\r\n正文\r\n`（UTF-8 BOM）在阅读中输入：compositionstart、DOM/input变为“正文ni”、blur、compositionend、最后DOM/input变为“正文你”。缓冲区只接收最终“正文你”，不能先接收“正文ni”；保存前Markdown、批注YAML和画布JSON的bytes / mtime保持。最终DOM先到、input后到，以及传统input先于end的顺序分别核验。合成事件不当作物理IME证据。
2. end后的完成阶段保持既有输入活动保护，最终input可以重新安排读数；保存、批注和离开不能穿过该阶段。重复blur不重复提交，取消组合且无尾随input仍能解锁；重新聚焦 / 新组合 / Escape / 恢复 / 文档或源版本替换 / 卸载使旧任务失效，迟到async回复不能恢复或覆盖新的输入。活动租约分别释放且平衡，不叠加全局composing计数。
3. 非组合的普通blur仍同步应用正文，单次显式保存保持原体验。输入期间点击保存应先提示完成当前输入，不发起保存IPC或禁用当前宿主。完成后显式保存、共享撤销 / 重做及BOM / CRLF精确字节往返通过，现有锚点和sidecar安全门槛保持。
4. 正文先有未失焦的“正文保留”，再粘贴多行文本。拒绝粘贴的反馈只保留本次粘贴内容，不能因此丢掉此前正文草稿。尚未交接的草稿在临时禁用 / 恢复编辑时保持原DOM及dirty，连续两次暂停、其间没有重新聚焦也要保留；关闭反馈后可继续聚焦、失焦，将原草稿作为一次共享编辑应用。真实源 / 文档身份更换、显式恢复，或已经交出草稿后的权限变化应恢复原渲染内容；跨强调 / 链接替换被拒绝时，尝试内容留在反馈，正文恢复原排版。迟到旧任务仍须失效。
5. 真实Windows WeType在最终同包中验证阅读候选、确认、取消、活动候选期间保存零写入、失焦提交及跨模式历史。记录可信原生事件、实际窗口和包身份；若前台 / 人工输入干扰使样本失效则保留，不以合成顺序替代。未证明当前WeType原生触发上述旧缺陷，不作这样的归因。
6. 聚焦生命周期测试、类型检查、全量单测、独立干净构建、同包完整窗口及实际Vite回归通过。GUI串行，测试结束停止自有窗口 / 服务；三项用户原修改摘要保持并排除提交。本批不改Markdown / YAML / JSON格式、IPC权限或依赖版本。

## 实现与当前证据

阅读编辑会话在compositionend后等待一帧及随后的浏览器task，再读取实时DOM；尾随input会重新安排完成阶段。完成阶段与已发出的异步提交各自拥有活动租约，避免重新聚焦 / 卸载提前解除已有写入保护。新组合、Escape、重新聚焦、源身份更换或卸载均使旧回调失效；普通blur保持同步交接，旧回复不能清除另一个正文块新持有的草稿状态。窗口捕获单独拥有composing计数，并剔除已断开目标。保存、批注保存与变更、模式切换和文档离开沿用同一活动检查。

旧QA4冻结包在受控事件顺序的第二场景明确失败：最终预期“正文你”，共享源码实际为“正文ni”；传统input先于end的第一场景通过。专项扩为16场景后，当时的脚本再次运行旧包，仍在同一断言失败。这证明产品处理事件顺序存在缺口，合成CompositionEvent / InputEvent不证明物理WeType自然产生该顺序。

初始运行时 `eca8d19` 的独立干净构建通过npm ci、类型检查、495/495单测和make，原15场景专项通过。复核继而确认权限变化会重建已有输入的段落；该A包在实际Ctrl+V及受控ClipboardEvent两版检查中，均在“暂停权限后旧DOM仍连接”的断言失败。B运行时 `40aced2` 改为权限变化保留DOM，16场景及B包真实WeType通过；但完整回归在UX3复现被拒绝的跨叶替换仍留在正文，B不作为最终交付。

C运行时 `653bff5` 用明确的草稿所有权区分两类权限变化。cleanup在dispose前保存ownsDraft：未交接草稿保留，已交接内容由源码 / 反馈持有，权限变化须恢复原children；新会话即使元素已失焦也继承保留草稿的所有权，不移动DOM焦点。旧Promise继续受代次 / 存活 / 焦点检查约束，不能通过无条件迟到恢复覆盖新输入。第20项纯测试覆盖交接、重新聚焦及旧拒绝回复；16场景内补第二次没有refocus的暂停，C专项与原UX3定向均已通过。

当前16场景中，粘贴回归使用可信CDP insertText产生已有正文草稿，再将合成ClipboardEvent发送给实际产品handler，避免修改系统剪贴板；分别断言input可信、paste为合成事件，随后操作实际反馈按钮并核验失焦提交。其余组合事件同样明确标注来源，浏览器可信事件与物理键盘 / IME验收分别记录。

## AX实验的退出决定

本批先沿用QA4冻结ASAR，以真实原生客户端激活四项AX特性，比较失活阅读CSS去掉content-visibility:hidden及200长段落分成1400相邻Text节点。正文SHA、完整高度、500个原Range引文与连接状态、原文三文件均保持；探针恢复后再做原始对照。两项均没有消除约0.53秒长任务，全部已恢复，不交付这些DOM / CSS更改。

原始对照长任务563ms；去掉失活hidden规则两次为554 / 562ms，并增加约110ms任务；相邻Text拆分为558 / 557ms；恢复后为516 / 526ms。探针焦点为false，仅作为根因筛查，不能判正式预算通过或计算可靠收益百分比。实际引擎为Electron44.4.1 / Chrome152.0.7977.78；本批检查该引擎源码后，未找到产品可调用的原生实时AX序列化分片预算，snapshot专用超时不能当作实时客户端性能修复。完整正文、辅助功能特性及模式hidden / inert隔离继续保留。

历史单次大跳、原生AX性能、卸载残留、长期内存与物理设备 / 发布门槛继续独立跟踪。
