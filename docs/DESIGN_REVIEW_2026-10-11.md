# MerMarkd 简约性与实用性设计评审

> 更新于 2026-10-12。状态：初始评审保留作设计依据；UX1 已完成并合并，UX2 已完成并通过打包回归，其余 UX3–UX5 待推进。优先级仅用于本次体验改进，不代表 P0 阶段已完成。UX1/UX2 不改变数据模型或三文件保存合同。

## 结论

当前最影响产品成熟度的是操作层级和行为一致性：辅助操作占据默认工作区，界面重复解释内部保存机制，同一个功能分布在多个入口，部分提示与实际能力不一致。下一轮应先修正这些问题，再统一布局与视觉样式。

目标体验：用户打开文件后立即看到正文；选中文字才出现批注操作；需要改原文时能准确判断哪些内容可编辑；进入画布后主要看到章节与关系；只有执行结构调整或遇到真实冲突时才展开详细说明。

## 已有基础应继续保留

已经实现的共享文档会话、跨模式撤销、阅读位置恢复、选区批注、结构预览、独立批注与画布文件，以及画布“更多 / 导出”分组，都是本轮继续改进的基础。无需重新设计这些底层合同。

简化界面时，Markdown 原文、批注 YAML 与画布 JSON 仍须分别核验和保存；不能通过自动改写 Markdown、取消结构预览、忽略冲突或在 dirty 状态写入旧版本锚点来降低操作成本。

## 目标工作区

```text
┌───────────────────────────────────────────────────────────┐
│ 目录  文件名 · 未保存     阅读 | 源码 | 卡片    查找 保存 ⋯ │
├────────────┬──────────────────────────────────┬───────────┤
│ 目录/最近  │                                  │ 批注/属性 │
│ 可收起     │       当前模式的主要内容         │ 按需展开  │
│            │                                  │           │
└────────────┴──────────────────────────────────┴───────────┘
```

- 文件名只在外壳显示一次；Markdown 自身的标题完整保留。
- 阅读默认展示正文和用户偏好的目录；零批注时不默认展开空批注栏，创建批注时打开。
- 源码默认展示完整编辑器、可收起目录和简短行列状态；源码结构工具不常驻。
- 画布默认展示场景和精简工具，右侧检查器由用户打开；导出继续明确作用于完整场景。
- 只有异常需要持续提醒。成功反馈使用短暂状态或就地反馈；“原文件未修改”“v2 已载入”“进入撤销栈”等不作为日常主文案。
- 右侧当前任务面板和文件菜单都应保留稳定入口，不把所有功能都藏进无标签图标。

## 下一步实施顺序

### UX1：统一承诺和默认首屏（2026-10-11 已实施）

范围：外壳、阅读页标题区、源码页头部、能力提示。

1. 统一模式名称与编辑能力提示，去掉与实际行为冲突的“只读”。
2. 合并正文保存入口；把放弃/恢复/另存为归到固定文档菜单或状态入口。已有文件另存为未完成前不提供可点击死路。
3. 移除正常状态下的第二条维护工具栏、重复文件名大标题、常驻结构表单；查找保持快捷键及可见入口。
4. 聚合状态必须接收真实的正文、批注、画布结果。当前 `workspaceStatuses.canvas` 只由正文/批注条件推断，不能拿“可编辑”代表画布已经保存成功。

验收：干净文档首屏没有恢复/结构表单，原文第一段更早进入视野；同一状态下标签与命令能力一致；保存/失败/dirty/新建/外部冲突各状态可区分。不以隐藏失败换取视觉整洁。

### UX2：统一面板与专注模式（2026-10-12 已实施）

范围：共享左右栏、目录、批注、属性、响应式容器。

1. 建立一份外壳面板状态，接入三种视图；左栏容纳目录与最近文件，右栏容纳当前任务信息。
2. 宽窗口面板进入正常布局；窄窗口只打开一个辅助抽屉，并支持 Escape、焦点归还和键盘循环。
3. 专注模式临时收起辅助区，退出后还原原状态；不丢批注草稿、滚动位置、章节选择或编辑历史。
4. 画布默认使用可用窗口高度，编辑器与侧栏各自滚动，移除必须手动调画布高度才能获得空间的默认体验。

验收：1200×800、800×700、420×800 CSS px 下控件可识别可达、无意外横向页面滚动；专注模式三视图行为一致；切换模式和面板不写 Markdown 或任一 sidecar。窄窗口是桌面可缩放验收，不代表手机产品验收。

实现说明：共享目录与任务面板已进入外壳，1100 CSS px 以下复用单抽屉。Ctrl+Shift+F 可在抽屉内部进入/退出专注模式，恢复原控件焦点；批注和关系标签草稿在隐藏面板时保持挂载。画布使用剩余视口高度；源码目录跳转会显式显示光标行。新 UX2 打包版回归验证了上述尺寸、焦点、草稿、滚动、撤销和三文件零写入。批注在跨模式、dirty 正文中的连续使用仍属于 UX3。

### UX3：打通阅读、编辑、批注的连续操作（2026-10-13 当前切片已实施）

范围：受限阅读编辑反馈、保存后续操作、批注只读参考。

1. 多行粘贴、Enter 和不可编辑块提供统一可执行反馈；复制与阅读不受无关编辑限制影响。
2. 正文 dirty 时仍可查看批注内容，不能把旧锚点作为当前正文定位依据。
3. “保存正文并继续批注”保存成功后重新建立选区映射；文档身份改变、原选文变化或出现歧义时保留意图并要求重新选取，不自动附着。
4. 优先验证高频编辑能力：普通段落换行、跨强调/链接的选区、中文 IME 与多行纯文本粘贴。通过局部源码补丁和往返门槛后再开放，不一次承诺完整富文本编辑器。

验收：完成“改一句话 → 保存 → 批注 → 源码撤销/重做 → 返回阅读”的任务；保存失败保留可恢复内容，dirty 期间无 sidecar 提交。涉及文件变更增加针对性核心测试和打包版回归。

实现说明：已完成 dirty 批注参考、保存正文后继续批注、同文档跨模式草稿、保存后撤销历史与受限编辑反馈。257 项核心/持久化测试和 14 组打包窗口回归通过，见 [UX3 验收](UX3_ACCEPTANCE.md)。换行、多行粘贴和跨块输入目前仍引导到源码，不扩大富文本编辑范围；真实中文 IME 门槛仍待验收。

### UX4：精简画布的内容和操作（2026-10-13 当前切片已实施）

范围：卡片视觉、按选中项显示的工具、结构预览、导出入口。

1. 区分章节组边界和本节内容卡；减少零值计数、重复路径与常驻图标。
2. 选中卡片显示卡片相关操作，选中箭头显示标签/删除；保留可由键盘触达的菜单入口。
3. 结构预览保留在画布任务上下文：先显示“某章节移到某章节之下”、标题级别变化及受影响批注，再提供源码差异检查；仍须明确确认和显式保存。
4. 延续已有“更多 / 导出”分组。导出面板说明完整场景、格式、预计尺寸和超限原因；不要通过裁切获得看似成功的导出。

验收：三层嵌套、长正文、重复标题、跨层箭头场景；普通拖动只改变画布数据；结构取消恢复位置，撤销恢复内容；导出包含视口外箭头和标签。不能以少按钮为理由取消这些门槛。

实现说明：卡片与组的视觉分层、选中项属性、画布内预览/撤销及完整导出预检已完成，见 [UX4 验收](UX4_ACCEPTANCE.md)。262 项单元测试及 15 组打包窗口回归通过；实际导出尺寸限制继续保留，不宣称全部 P0 门槛完成。

### UX5：统一视觉与补齐发布质量（2026-10-14 视觉与菜单切片已实施）

范围：字体、间距、状态色、焦点、微反馈，以及当前构建的真实窗口验证。

- 使用中性底色和一套主交互色；批注颜色保留语义。收敛为少量圆角、描边和间距规格。
- 先验收阅读排版和控件可读性，再增加有限动效；高频输入、模式快捷键和查找不加入等待动画。
- 补测真实中文输入法、安装版 DPI、较长文档和大量批注；性能预算依据测量再定。当前大文档 Worker/虚拟化仍未完成，外观调整不应被表述为性能已改善。
- 生产打包与真实窗口验收是发布条件。UX1 开发使用本机 Electron 44.4.1 缓存完成生产打包、Squirrel 安装包生成和打包版窗口回归；真实输入法、多显示器 DPI 与安装/卸载全流程仍需后续验收。

实现说明：字体、间距、配色、状态详情和键盘焦点已统一；画布菜单支持互斥、方向键、Escape、外部关闭及视口边界。262 项单测和 16 组打包窗口回归通过，额外完成 DPR 1/1.25/1.5/2、200% 页面缩放、高对比与核心性能样本复测，见 [UX5 验收](UX5_ACCEPTANCE.md)。这些验证不代替真实 IME、物理多屏、安装/卸载或 renderer 大文档门槛；后续先测量界面响应性，再推进后台解析与过期结果保护。

## 建议第一批的明确边界

本轮已实施 UX1，交付一版“更少默认控件、文案与能力一致”的工作区。触及文件事务的另存为、扩大阅读编辑范围、批注草稿提交分别进入后续切片。这样第一批就能看到首屏变化，同时不会把安全保存与界面整理绑成一次大改。

建议用五个固定任务验收后续成果：打开最近文件、找到指定章节并修改、选文批注并复制摘要、整理一组章节后取消/确认、导出完整画布。记录每项是否完成、寻找入口的停顿、无效点击和模式切换次数；这些比按钮数量更能判断是否实用。

## 参考原则

- Microsoft 的 [Command bar 指南](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/command-bar)建议按重要性安排主命令，次级命令进入更多菜单，窄窗口采用溢出菜单，并保持跨页面命令位置一致。本评审把这些原则用于收敛 MerMarkd 的重复工具栏，不要求替换技术栈。
- Obsidian 的[侧栏说明](https://obsidian.md/help/sidebar)和[视图与编辑模式说明](https://obsidian.md/help/edit-and-read)提供了面板开关和模式语义的可对照案例。这里只借鉴功能归属与名称清晰度，不把其信息架构整套搬入单文件产品。

本轮使用 `emil-design-eng` 技能的界面层级、上下文操作与反馈审查方法；具体优先级来自本项目当前代码和文件边界。
