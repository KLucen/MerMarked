## 实验与退出条件

1. 用同一打包版本、同一5MiB / 200标题 / 500高亮样本，对照常驻contenteditable、只读DOM、保留单宿主以及静态可聚焦段落。通过真实原生客户端激活实际AX特性，记录focus / 可见 / 最小化、同源mark、完整toplevel trace及三文件bytes / mtime。DOM探针仅作根因筛查，不能作为正式产品修复。
2. 常驻1001宿主、只读0宿主、单宿主与静态可聚焦段落的同进程A-B-A对照，仍有约0.53秒renderer长任务；Browser成本有下降，但不能据此宣称整条路径达标。不交付没有解决主要卡顿的编辑生命周期改造，也不重复QA3的分批AX暴露原型。
3. 旧包真实CDP AX树中，200个正文heading名称全部为重复操作提示；仅移除title会变为空名。修复须让标题名称取自其当前实际内容，覆盖h1–h6、中文/emoji、重复/格式化及不在目录中的嵌套标题；输入、Escape、提交和历史操作后仍准确，不能用源码属性检查替代实际AX行为。操作提示属于描述，不充当正文名称。
4. 同包确认语义正文、末尾标记和500高亮，保持源码映射的安全约束、编辑生命周期与模式hidden / inert隔离。记录内部完整AX检查和真实原生客户端快照的区别：大样本原生document_text截到19999字时不能宣称全文或尾部已通过。正式计时与trace分开；记录ready之后的renderer及end之后的Browser任务，不将提前ready或失焦 / profiling样本判成预算通过。
5. 类型检查、全量单测、干净构建、标题专项和同ASAR窗口回归通过，再验证实际Vite路径及原生小样本名称。三项用户原修改保持且不提交，GUI测试串行，结束时停止自有进程与服务。没有编辑生命周期改动，不将旧物理IME证据冒充本批重新验收。
6. 专项在初始标题修复包中确认emoji尾部追加被安全拒绝，纯核心复现同样覆盖前插与共享代理位的替换。以完整字素规划编辑跨度，保持单一exact leaf、源码语法与现有resolveSelection校验；组合重音 / ZWJ / 肤色 / 旗帜 / BOM+CRLF不规范化或拆分，跨叶和编码边界继续保守拒绝。修复后须重新冻结构建及回归，初始包的通过结果不能替代最终包。

## 诊断边界

旧包对照中，原生查询激活了nativeAPIs / webContents / inlineTextBoxes / extendedProperties。首轮被其他应用遮挡，焦点失效，保留为诊断；用户确认恢复前台后才继续普通对照。trace中Browser事件在测量end之后仍排队，因此会话工具补充明确的1500ms观察尾窗；这不是产品延迟，也不是正式性能通过条件。

未采用content-visibility:auto作为本批修复。[CSS Containment草案的辅助功能约束](https://www.w3.org/TR/css-contain-2/#accessibility)允许在部分需要layout的可聚焦内容上省略屏外辅助节点，不能仅凭DOM仍存在就承诺完整AX。标题修复参照[WAI-ARIA名称与描述规则](https://www.w3.org/TR/wai-aria-1.2/#aria-labelledby)，并以当前固定Electron的实际AX结果验收。
