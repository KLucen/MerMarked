## 用户行为与写入边界

| 场景 | Before | After（本批目标） | 内容文件边界 |
| --- | --- | --- | --- |
| 已有布局后新增根章节、子章节或子树 | 新卡片可触发整图整理，已有手动坐标改变 | 为新卡片安排位置，保留已证明身份的原卡位置、正文偏好、折叠和箭头 | 载入和模式切换不写三文件；显式保存布局仅写画布 JSON |
| 折叠父章节下新增子章节 | 隐藏节点没有 DOM 测量 | 为隐藏新增节点提供布局，不展开它来测量，也不等待其挂载 | 原折叠及三文件保持，直到显式画布保存 |
| 外部正文变化使旧章节不能安全匹配 | 身份进入待修复，不能猜测连到替代章节 | 保留未匹配旧记录和原箭头端点；其余已匹配章节不被全图整理 | 不把未匹配记录伪装为当前已定位章节 |
| 坐标范围内没有安全新增位置 | 自动放置不能安全继续 | 保留已知布局并禁用写入；用户可明确“重新整理临时布局”，检查后再显式保存 | 拒绝与临时整理均不写三文件；保存视图才提交 JSON |
| 画布查找 | 查标题但入口只称“查找卡片”，缺少统一快捷键和可浏览路径结果 | `Ctrl+F` 聚焦并选中查询，明确“搜索章节标题”，按源码顺序浏览含路径的结果；Escape/清除按钮清空 | 查找和定位不保存视口、折叠或其他内容文件 |
| 阅读当前章节到卡片 | 缺少明确的定点入口 | 用户主动“在卡片中定位本节”；隐藏章节定位到可见祖先，不隐式展开 | 定位和普通模式切换均零内容文件写入 |
| 定点定位后的普通模式往返 | 历史定位请求可能在重挂载时再次消费 | 普通切回卡片恢复原保存视口，旧请求不抢占 | 保留磁盘视口与三文件 bytes/mtime |

已有卡片的位置是其当前 Markdown 派生父卡下的相对坐标。单纯新增根卡或向现有父卡添加子卡时，旧卡世界坐标也应保持；父容器外框可按新内容派生增长。新增父标题包裹已有章节会改变 Markdown 归属，不能扩大承诺为该情形下旧卡世界坐标也绝不变化。保守身份匹配仍适用，不能因同名标题就继承旧卡或重接箭头。

首次没有画布 sidecar 的文档继续初始化；用户显式“自动整理”仍允许全图重新布局。被动增量布局不创建 sidecar。源码 dirty、事务恢复、冲突和组合输入的既有安全门槛继续保留。

## 新专项与退出条件

专项脚本为 `tests/e2e/ux9-layout-navigation-packaged.mjs`，计划使用实际打包程序、每次独立绝对 user-data 路径和已核验进程身份。报告与截图以 `MERMARKD_QA_ARTIFACT_PREFIX` 指定唯一前缀，并拒绝覆盖旧报告。失败保留生成文档和原报告；成功仅清理已核验的自有临时目录。
