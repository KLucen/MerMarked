# B0 验收样本

> B0 先验证核心编辑与画布合同，不把未实现的阅读富文本编辑器写成已完成能力。普通编辑验证使用内存候选，只有显式保存才允许进入 Markdown 发布流程。

## 样本 A：源码局部编辑

初始 Markdown（文件字节包含 UTF-8 BOM 和 CRLF）：

```markdown
# 中文😀

引用定义 [文档][ref]

> 引用段落

| 名称 | 值 |
| --- | --- |
| alpha | **正文** |

[ref]: https://example.com
```

操作：在编辑会话中把 `正文` 替换为 `新正文`，再执行撤销和重做。

预期：

- 候选只替换目标 UTF-16 半开范围，中文、emoji、引用、表格、定义和 CRLF 原样保留。
- 撤销回到完整原始正文，重做恢复 `新正文`；新的编辑会清除重做分支。
- dirty 候选不写 `.md`、批注 YAML 或画布 JSON；显式保存仍交给现有主进程 Markdown 保存门槛。

当前结果：核心编辑事务已通过；阅读视图中的富文本直接编辑、IME、剪贴板菜单仍未实现。

## 样本 B：画布 v1 到 v2 内存迁移

操作：加载含父章节、子章节、箭头和折叠状态的 v1 画布 JSON。

预期：

- 卡片 ID、锚点、箭头、视口和原 `position` 不变。
- `collapsed` 只迁移为 `descendantsCollapsed`。
- 新增 `contentPosition: { x: 0, y: 0 }` 和 `bodyDisplay: "preview"`，不把摘要伪装成全文。
- 打开旧文件不写盘；明确保存时才由后续 B2 画布写入流程决定是否升级 JSON。
- v2 严格拒绝旧 `collapsed` 字段、未知字段、非法正文显示状态和错误端点。

当前结果：迁移、严格校验和 JSON 往返已通过核心测试；React Flow 投影、自由定位和双折叠将在 B2 实现。

## 样本 C：编辑引擎选型门槛

候选：现有原生 textarea 源码编辑、CodeMirror 6 源码编辑、ProseMirror 类渲染编辑。

暂定判定：

- B0 只接受不破坏原文的共享事务模型，不能因为编辑器渲染而重序列化整个 Markdown。
- CodeMirror 6 可作为源码编辑增强候选，但在确认依赖前要测中文 IME、CRLF/BOM 和未改块字节保持。
- ProseMirror 类渲染编辑只有在能从事务生成局部源码补丁、保留未知块并通过撤销/外部冲突样本后才进入 B5；本批不安装新依赖。

## B0 进入下一批条件

- 核心事务和 v2 迁移测试继续通过全量单测、类型检查和打包。
- 阅读富文本编辑仍标为未完成，不把 B0 结果描述为完整 Typora/Obsidian 式编辑。
- B1 可以在保持现有保存门槛的前提下调整工作区外壳；B2 才接入 v2 画布状态和独立内容卡。
