# MerMarkd 试用反馈与下一轮迭代方案

> 2026-10-01。本文根据本轮八项试用反馈重新规划。状态：B0 核心合同切片已实现，B1–B6 仍待实施；这里的交互、阈值、技术候选和性能预算不代表已经全部实现或验收。当前实现仍以 `PROGRESS.md` 的记录为准。用户新的产品方向优先于旧文件中“阅读模式只读”和“固定结构投放区”的规定。

本轮 B0 已落地 `canvas-state-v2` 的只读内存迁移/严格校验，以及 `MarkdownEditSession` 的局部替换、revision、撤销和重做核心。阅读富文本编辑、React Flow v2 投影和工作区外壳仍按下表批次推进。

## 1. 产品方向

MerMarkd 的下一轮目标是：在同一份本地 Markdown 上连续完成阅读、写作、批注和章节整理。三个视图分别服务于“排版内容中直接编辑”“查看并编辑完整源码”“用卡片理解和调整章节”。切换视图保持位置、选区、未保存内容和文档撤销历史。

对用户继续使用“阅读 / 源码 / 卡片”三个简短名称。“阅读”支持编辑渲染后的内容，可通过文档菜单启用只读保护；“源码”显示完整原文。普通浏览、选择和切换视图都不自动修改文件，直接编辑才进入未保存状态。保留 `Ctrl+S` 显式保存与崩溃恢复草稿。

需要保留的基础合同：

- `.md` 是正文与标题树的唯一来源；本节正文不复制到画布 JSON。
- 高亮、便签、标签与锚点继续保存在独立 YAML，右键的“高亮”属于阅读批注。
- 布局、正文折叠、后代折叠、箭头和视口属于画布伴随状态；应用外壳的侧栏开关属于应用偏好。
- 结构候选使用源范围变换、重解析、预览、确认、撤销和显式保存。手势提示本身不修改文档。
- `.md`、YAML、JSON 分别校验版本，外部变化不覆盖；锚点不能确定时保留待定位。

## 2. 反馈与实现核对

| Before | After | Why |
| --- | --- | --- |
| 一个 `collapsed` 隐藏后代；正文一直显示最多 160 字摘要 | 正文与后代分别折叠；正文支持完整的直接正文 | 用户可以单独收起长正文，同时保留结构 |
| 父章节内容与子树容器是同一个节点，内容固定左上角 | 本节内容卡与章节组边界分开，内容卡有独立位置 | 父章节内容可以在组内自由摆放 |
| 每张卡常驻“拖到此处设为子章节”条 | 拖动时计算重叠候选，短暂停留后提示可移入 | 减少占用，手势结果在松手前可见 |
| 子卡位置被钳制在父正文下方，没有拖出候选 | 冻结拖前组边界，越界后提示提升或移至顶层 | 能直接解除包含关系，避免被自动扩容吞掉 |
| 阅读只读，源码可编辑，撤销实现依赖源码组件 | 两种编辑视图共享文档缓冲区、命令和撤销历史 | 写作不必反复跳回源码处理日常操作 |
| 有选区高亮与便签操作条，缺少统一右键菜单 | 复制、粘贴、剪切、删除、格式与高亮进入选区菜单 | 与常见桌面编辑器的习惯一致 |
| 品牌、文件信息、打开区、模式栏及画布工具栏分层常驻 | 开始页负责打开文件；文档页使用紧凑导航和可收起两栏 | 把空间让给文档和画布 |
| 动效主要为滚动和导出旋转，无完整交互状态反馈 | 用短、可中断的反馈表达目标、归属、取消与侧栏状态 | 动效解释行为，操作保持响应及时 |

核对位置：`src/renderer/app-shell.tsx`、`src/renderer/main.tsx`、`src/renderer/canvas-view.tsx`、`src/core/canvas-scene.ts`、`src/core/canvas-state.ts`、`src/core/canvas-card-content.ts`。这些发现基于当前代码与已有打包截图，未进行新 UI 实现。

## 3. 页面与布局

### 开始页

无文档时展示打开文件、拖入文件、新建 Markdown 和最近使用文件。最近记录只保存路径与打开时间；失效路径可移除。新建文档先进入可编辑缓冲区，首次保存由文件选择器确定路径。品牌只在开始页和关于窗口出现。

打开文档后进入完整工作区。再次打开使用应用菜单、左栏或 `Ctrl+O`；拖入新文件时出现临时文件投放反馈。未保存内容先按现有流程处理，不能因拖入或切换文件丢失。

### 文档工作区

建议单条约 40 px 的紧凑导航：左侧菜单与左栏开关，中间三个视图切换，右侧查找、保存状态入口、右栏开关和系统窗口控件。完整文件信息放在右栏；未保存圆点、保存失败或冲突入口保持可见，不因收起右栏隐藏必要状态。

左栏提供最近文件和当前文档目录，三视图共用当前位置。右栏按当前任务提供批注、文档信息、卡片属性三个标签；路径、编码、恢复记录等只在用户展开时显示。选中卡片不强制弹出右栏。目录定位、备注跳转和切换视图保留章节与附近源位置。

两栏默认收起并记住用户选择；宽窗口打开时使用正常布局，窄窗口使用可关闭抽屉。正文保持可读行宽，画布使用其余完整区域。抽屉支持 `Escape`、焦点返回和键盘循环；收起时隐藏控件不能进入 Tab 顺序。

画布常用的定位、缩放、整理、导出放入小型工具带或菜单；关系编辑进入右栏。阅读页的文件大标题、正常批注计数与操作说明移入两栏，正文从文档自己的标题开始。失败和冲突仍需明确提示。

## 4. 卡片模型与手势

### 两种视觉职责

每个章节保留一个稳定业务 ID。该章节有本节内容卡；存在子章节时，还派生一个章节组边界，容纳本节卡与子组。组的父级只来自 Markdown 标题树，不在 JSON 创建第二套可独立变化的章节结构。

拖本节卡标题只移动本节卡；拖组边界上的窄标签移动该章节整棵子树。组的空白区域继续用于平移或选择，避免覆盖整个画布的拖动区域。父章节自己的内容卡可以摆在组内任意位置；碰撞提示帮助对齐，系统不把它钳回左上角。组整体移动保持内部相对位置。

卡片正文支持文字选择和复制，文字拖选不触发卡片移动。双击或“编辑本节”进入同一章节的阅读编辑位置，返回画布保留视口和选中卡。卡片右键承载正文展开、后代展开、移入、提升、复制与编辑本节，内容编辑仍复用同一文档会话。

归属通过细边界、低对比背景、小型组标题、本节标识及选中时的路径表达。仅选中或结构候选时强化边界；避免为所有层级涂不同强色。用户箭头用端点箭头表示，自动层级主要由嵌套与目录表示。

正文折叠只留下标题与必要操作；后代折叠隐藏所有子孙但保存每个子章节自己的展开状态。两种折叠组成四种可用状态，叶章节也能收起正文。新文档默认使用紧凑正文预览，可选择展开完整直接正文；显示全文后复用同一安全 Markdown 管线，表格和代码块在自身范围内滚动。长正文不被截断后冒充全文。

### 画布版本与坐标

建议画布 v2 中将旧 `collapsed` 迁移为 `descendantsCollapsed`，加入独立正文显示状态及本节内容位置。正文显示状态可采用 `hidden / preview / full`，明确区分原摘要与真正全文。原 `position` 表示章节组在上一层的位置，本节内容位置表示其相对自身组的偏移。

v1 加载时只在内存迁移，保持 ID、原坐标、折叠、箭头与视口；第一次明确保存时才写 v2 并保留可恢复的旧版本。未知版本仍只读，旧应用不得覆盖 v2。独立 group 渲染 ID 不进入持久化箭头端点。

核心层统一计算组原点、世界坐标和局部坐标。换父级时按世界位置转换相对坐标；组向左或向上扩展时同步调整原点和内部偏移，避免全组跳跃。组大小由本节卡与子组的完整边界派生。

### 重叠移入

取消常驻投放条。拖动状态建议为 `自由移动 → 候选 → 可移入 → 松手预览 → 确认 / 取消`。

候选起点参数：被拖内容卡的有效矩形约 60% 与目标重叠，停留约 250 ms 后进入可移入；退到约 40% 以下解除。阈值存在滞回，避免边界闪烁。参数先通过样本验证再固定；超长展开卡采用从标题开始的稳定操作矩形，不能让长正文使移入永远达不到比例。

优先命中目标的本节卡；组空白区域参与时选择最深、最小的有效章节组。排除自身、后代、当前父级、前言/全文虚拟卡及未解析节点。多个目标不明确时显示待选择状态，不猜测父级。无候选时松手仍是普通布局移动。

候选边界立即反馈；就绪后显示目标名和“设为子章节”的短提示。松手只生成预览，显示源章节、目标章节、插入位置、标题级别变化和批注影响；完整源码差异可展开。确认加入文档撤销单元，显式保存才落盘。`Escape` 和取消恢复拖前布局及视口。

### 拖出独立

拖动开始时冻结原组边界，不让组随着被拖卡片不断扩大。以卡片中心离开边界、包含比例降低及越界距离共同判定；约 24 CSS px 越界和 180–250 ms 停留可作为初始验证参数。

拖出直接父组但仍在上一层有效祖先内，提示“提升为原父章节的同级”；离开全部祖先时提示“移至顶层”。拖入新章节的就绪候选优先于拖出。提示明确最终父级和章节级别。

跳级标题按实际祖先计算：`H2` 父章节下的 `H4` 变为该父章节的兄弟时应选择 `H2`，简单减一级仍可能留在原父下。顶层候选明确显示是否变为 `H1`；特殊文档的级别可在预览中调整，再重解析核验。插入位置先沿用已验证的该层末尾语义，并显示给用户。

拖出同样复用预览、确认、取消、撤销和三文件保存。键盘与卡片右键提供“移入章节”“提升为父级同级”“移至顶层”，保证不依赖鼠标动画才能完成操作。

## 5. 阅读编辑、源码编辑与选区菜单

### 一份文档缓冲区

两种编辑视图共用内容、revision、选择映射、命令、恢复草稿和文档撤销历史。阅读中加粗后切源码能看到对应标记；源码撤销后切回阅读看到相同结果。普通布局有自己的撤销范围，焦点和命令名称明确区分“撤销文档修改”与“撤销布局”。

既有 `useMarkdownEditor` 的排队 IPC、dirty 守卫和主进程保存路径继续复用。下一步补充可证明的文本编辑事务与位置变换，覆盖标题、正文、跨段选择、格式、粘贴和章节命令。批注和卡片身份要跟随这些变换；不能在频繁改标题后把所有卡片简单判为新卡。

### 编辑引擎先做小样本验证

优先验证成熟的 CodeMirror 6 源码编辑与语法装饰能否实现要求的渲染编辑体验，保留原文作为唯一内容。阅读侧需要标题、列表、引用、代码、链接等真实可编辑呈现，不能用一个静态预览冒充编辑器。

若渲染编辑需要 ProseMirror 类块编辑器，先证明其输入事务能映射为局部源码补丁，并能保留未参与编辑的块；再决定依赖。引擎选型属于原型关口，不在本规划中直接安装或替换。

必须通过：中文 IME 组合输入、跨格式选择、方向键、Enter/Backspace、剪贴板、撤销、长文档、BOM/CRLF、引用定义、HTML、转义、同名标题与无操作保存。未知或不能无损编辑的块以保留原文的块呈现，并提供源码入口；未编辑它时保存不能重写它。不从整个渲染 DOM 重新生成 Markdown。

### 右键与浮动工具

菜单按上下文只显示可用命令：复制、剪切、粘贴、删除；加粗、斜体、引用、链接；高亮取色和添加便签。复制默认复制可见文字，复制 Markdown 可作次级选项。链接和代码块提供各自的操作，无选区时剪切与删除不可用。

加粗、斜体、引用是正文编辑，进入文档撤销栈；彩色高亮和便签进入批注记录，不写 `==...==` 或内嵌 HTML 到 Markdown。引用默认作用于选区涉及的完整段落，预览范围与撤销结果一致；复杂跨块操作先支持可核验范围。

右键打开后保留原选区及对应 revision，菜单不因夺取焦点丢失目标。`Escape`、方向键、Enter、`Shift+F10` 与常见快捷键可用。复制不改内容；剪切先确认剪贴板写入成功，再执行文档删除。粘贴默认接收文本并做受控转换，富文本粘贴作为单独能力验收。

浮动工具只保留少量高频项，完整操作在右键或更多菜单。调色使用色块，格式使用图标，未知图标有提示。源码中的编辑菜单复用同一正文命令；源码若提供“高亮”，必须明确其仍为阅读批注且范围可核验。

### 未保存正文中的批注

当前 dirty 时批注写入冻结，渲染编辑后这会频繁打断阅读。建议后续允许对当前候选正文创建内存批注草稿，锚定候选 revision，并通过后续编辑事务映射；实际保存时核验 `.md`、YAML、JSON 三份基线后共同提交。

这一能力必须先实现恢复和映射：未保存批注随文档草稿一起恢复，放弃正文时明确处理相关批注；不能把候选锚点直接提交到旧磁盘摘要。未通过前继续显示明确的“保存正文后可添加高亮”，不让按钮无反馈失效。

## 6. 视觉与动效规则

使用本机 `emil-design-eng` 技能的交互频率、空间连续性、可中断与性能原则。工作区以中性纸白、浅灰和深色文本为主，蓝色表示文档选择，绿色表示结构可接受，琥珀色表示待处理；颜色不是唯一反馈。字体使用系统字体与中文回退，字间距固定 0，常规卡片圆角 6–8 px。

| 交互 | 建议反馈 | 目的与约束 |
| --- | --- | --- |
| 卡片拖动 | 即时跟随指针 | 不加会滞后于鼠标的位移动画 |
| 移入/移出候选 | 120–160 ms 的提示透明度，边界即时出现 | 保持目标稳定，配合目标名与图标 |
| 松手确认/取消 | 约 160–200 ms 的可中断落位反馈 | 保持空间归属；新拖动立即接管 |
| 鼠标打开侧栏 | 180–220 ms，退出更快 | 面板方向一致；正文布局不逐帧重排 |
| 右键菜单 | 100–140 ms，淡入并从触发点轻微缩放 | 选区不丢失，连续菜单可即时切换 |
| 正文/后代折叠 | 几何一次更新，内容轻淡入/淡出 | 不逐帧修改 200 张卡片高度 |
| 键盘操作、模式切换、撤销 | 即时生效 | 高频操作不等待过渡 |
| 减少动态效果 | 移除位移与缩放，保留静态目标反馈 | 信息仍可理解，交互仍完整 |

优先使用指定 `transform`、`opacity` 的 CSS transition 或 WAAPI；固定预算下先测帧耗时，按需考虑动画库。组边界与文本尺寸先一次测量，动画只解释已确定状态。不能借动画隐藏错误目标、慢解析或未保存失败。

| B3 结构拖动 | 重叠候选、停留/滞回、冻结父边界、拖出提升、目标提示和预览 | 快速掠过不改结构；自身/后代/六级/跳级/多目标/缩放/取消均正确；确认可撤销；原文与 sidecar 保存恢复继续通过 |
| B4 共同编辑命令 | 单一文档事务与撤销、源码右键/快捷键、文本剪贴板和格式命令、位置映射 | 一个命令可完整撤销；菜单过期 revision 不执行；BOM/CRLF 与未改块 bytes 不变；剪切失败不删除；批注和卡片身份安全迁移 |
| B5 可编辑阅读视图 | B5.1 标题/段落/格式/引用和中文输入；B5.2 列表/任务项/代码/链接/表格；B5.3 候选正文批注草稿 | 每个子批单独打包试用；两种编辑视图内容、选区与撤销一致；不支持块原样保留；重开/崩溃/外部改动不丢正文和批注 |
| B6 质量收口 | 动效复查、键盘/无障碍、独立导出、全文性能、安装/卸载与 DPI | 长标题/长正文/组/箭头标签完整导出；高 DPI 与减少动态效果通过；有完整大文件 UI 测量和干净用户安装证据 |

默认执行顺序为 B0 → B1 → B2 → B3 → B4 → B5 → B6。B0 中编辑引擎先验证，以便早发现最高风险；B1–B3 先交付可感知的空间与卡片改进。B5 不在一个巨大提交中完成。

每批都重新检查需求覆盖、状态流转、文件边界和未知版本，再执行类型检查、相关核心测试和打包 E2E。跨共享逻辑时运行全量单测；阶段门槛生成安装包。截图检查正常、窄窗口、高 DPI、长中文/emoji、无选区/菜单打开/取消/失败状态；发现问题先收尾修复再推进。

## 8. 实用性与质量债

这一轮应顺手解决的体验问题：跨视图保持附近内容位置；一键隐藏两栏；只读保护；恢复入口按待处理数量出现；新建/另存为；复制可见文字与复制 Markdown 的清楚区别。避免让用户为了改一个词经历打开面板、切源码、定位、保存、切回的长链路。

后续排队：批注摘要另存文件、画布当前可见/全部展开的导出选项、章节内部搜索、相对 Markdown 链接、可靠的外部文件变化通知、历史恢复文件的显式清理。首轮继续以单份 `.md` 的工作闭环为中心，跨文件图谱、同步和 AI 暂不扩展范围。

A8.6 的性能记录是核心函数和小型 UI 样本的首轮数据：200 卡片基准只为 1000 标题树的一部分构建场景；UI 样本为 3 张卡。RSS 是各阶段结束时采样值，不等于完整峰值；它们不能证明打包应用打开 5 MiB 和显示约 200 张卡的端到端性能。B6 增补真实大文件打开、输入、切换、布局、滚动、导出、进程峰值与主线程长任务。

大文件解析和布局需要 Worker、版本化取消与结果复用；折叠后不渲染后代，长正文按需渲染。先建议以目标样本“打开到可编辑 2 秒内、输入响应 p95 50 ms 内”为待测预算，固定硬件/样本/重复次数后再决定公开承诺。极端短行输入保留为独立压力样本。

安装验收仍需真正没有开发工具的新 Windows 用户或虚拟机；已有开发用户上的空安装目录与独立 `user-data-dir` 只能证明部分隔离。卸载回收安装文件与保留用户草稿需要分别定义，不能用手动删除替代卸载器通过。高 DPI 要覆盖 100%/125%/150%/200% 以及跨实际显示器拖动，导出尺寸不能只在 1×验证。
